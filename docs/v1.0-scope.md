# Nexus v1.0 スコープ定義

この文書は、Nexus v1.0 に含める成果と含めない成果を判断するための全体正本です。[GitHub Issue #9](https://github.com/m0o9l0v3/NexusMobile/issues/9) に基づき、棚卸しから作成された E0〜E9 の成果を、実装状況に依存しない製品境界として定義します。

個別 Issue の一覧や開閉状態はこの文書へ複製しません。進捗と個別の受入条件は [GitHub Issues](https://github.com/m0o9l0v3/NexusMobile/issues) で管理します。

## 文書の位置付け

情報が食い違う場合は、次の役割分担で判断します。

| 判断対象 | 正とする情報 |
|---|---|
| v1.0 への包含・除外 | 本文書 |
| API のルート、DTO、バリデーション | `openapi/public.yaml`、`packages/openapi/admin.yaml`、[API Foundation Policy](api-foundation.md) |
| Web LP の公開ルート、API 利用範囲、QR パラメーターの挙動 | [GitHub Issue #81](https://github.com/m0o9l0v3/NexusMobile/issues/81) |
| 個別成果の受入条件と進捗 | 各 GitHub Issue |

詳細文書、個別 Issue、既存 UI、到達可能なルート、リポジトリに残るコードは、単独では v1.0 の範囲を拡張する根拠になりません。API や画面の詳細を変更する場合も、本文書の製品境界を維持します。

## 正式な提供面

### 参加者向け iOS アプリ

参加者向けアプリ機能を正式提供するクライアントは `apps/nexus-ios/` の SwiftUI iOS アプリです。Home / Map / 案内 / 探すの4タブを提供し、施設検索、屋外・屋内地図、位置情報、目的地表示、経路案内をE1〜E6の基準データと配信基盤に基づいて実装します。旧Expoアプリ `apps/mobile-ios/` は2026-09-29に削除しました。

### イベント告知 Web LP

`web/` は、イベント告知、当日案内、iOS アプリのダウンロード・利用導線を提供する LP です。参加者向け iOS アプリの代替機能を提供せず、iOS と機能同期しません。動的データは、当日イベント一覧に必要な範囲の `GET /api/events/today` に限定します。

現在残っている Home / Map / Events、AI サポート、位置情報、ログ送信などの PWA 実装は移行前のプロトタイプです。LP に再利用する資産と最終的な公開挙動は Issue #81 で決定します。

### 管理ポータルと API

- `admin-web` と `admin-api` は、管理者認証、公開データとイベントの管理、MapDataset の検証・公開・ロールバック、運用ログの確認を担当します。
- `public-api` は、参加者へ公開できる read model の読み取りを担当します。DB 書き込みは、許可された匿名の `visit_logs` 受信だけを例外とします。
- 認証、参加者識別、チェックイン状態、QR トークンの発行・失効は `public-api` の責務に含めません。

## E0〜E9 の必須成果

E0〜E9 はすべて v1.0 の必須スコープです。`tier::0`、`tier::1`、`tier::2`、`tier::3`、`tier::parallel` は実施順や並行性を表し、任意かどうかを表すものではありません。

| 区分 | v1.0 で満たす成果 |
|---|---|
| `epic::E0` | GitHub repository、GitHub Actions CI、API 契約、製品境界を整備し、Web をイベント告知 LP へ移行できる基盤を確定する。 |
| `epic::E1` | 14 棟の canonical ID、建物・フロア・ノード・出入口の階層 ID、座標系、GeoJSON スキーマ、正式入口を含む基準データを確定する。 |
| `epic::E2` | MapDataset の draft、validation、publish、rollback、公開配信と、iOS 側の取得・キャッシュ・版更新を実装する。 |
| `epic::E3` | iOS の屋外地図、位置情報の権限と追従、14 棟の描画、施設検索、目的地表示、loading / empty / error / 位置情報オフ状態を実装し、旧モックを撤去する。 |
| `epic::E4` | 構内歩行ネットワークと端末内探索を整備し、主要 6 経路、経路ポリライン、距離・所要時間、簡易ステップ案内を提供する。 |
| `epic::E5` | `mb` / `ptb` の SVG フロアマップ、フロア切替、屋内ノードグラフ、同一階・階層間探索、屋外入口との接続、屋内目的地表示を提供する。 |
| `epic::E6` | SwiftUI iOS アプリで Home / Map / 案内 / 探すの4タブを提供し、Home の検索・各 UI 状態と、学校生活・寮生活・学科・交通アクセスの案内コンテンツを提供する。 |
| `epic::E7` | 管理ポータルの認証とトークン保管、スポット・開催日・イベント・MapDataset の管理、Dashboard・Logs の実 API 接続、validation・publish・rollback 操作を提供する。 |
| `epic::E8` | HTTPS / TLS、Secret 管理、DB 権限分離、rate limiting、backup / restore、deploy / rollback、CORS、本番シードパスワード対策を整備する。 |
| `epic::E9` | `apps/nexus-ios/`、探索エンジン、validator、主要6経路を対象に再現可能な自動・手動検証を行い、SwiftUIのアクセシビリティ、実機位置情報、電池消費を含めて合格する。 |

QR issue やワンタイムコードなど hidden beta に関する Work item を完了しても、その実装は正式な v1.0 提供機能には昇格しません。管理画面を含め、主要導線から外した状態を維持します。

## iOS 実装境界

- 現行の参加者向け iOS アプリは `apps/nexus-ios/` の SwiftUI プロジェクトです。
- 4タブは Home / Map / 案内 / 探すです。時間割専用タブはありません。
- 旧 `apps/mobile-ios/` ディレクトリは削除済みです。SwiftUIアプリのリリース受入とTestFlight確認は #87 で追跡します。

## QR の境界

v1.0 の QR は認証、チェックイン、参加者識別には使用せず、LP または公開リソースへ案内する resource link としてだけ使用します。

`?code=XXXX` の最終的な着地点、有効値、無効・未知値、未指定時、取得失敗時の挙動は Issue #81 で定義します。この詳細決定によって、QR 認証、参加者別 QR、トークンの発行・失効、チェックイン状態管理を v1.0 に追加することはできません。

## 対象外

次の項目は v1.0 の正式な提供・リリース判定に含めません。

- Expo / React Native 参加者アプリ、参加者向け PWA、および iOS アプリと同等の参加者向け Web アプリ
- Web と iOS の機能同期
- Android アプリの提供
- QR 認証、QR チェックイン、参加者別 QR、参加者識別、チェックイン状態管理
- 氏名、年齢、高校名、希望学科などの参加者プロフィール収集・保持
- hidden beta として残る QR issue、QR トークン、ワンタイムコード系機能の正式公開
- 旧 Web PWA の AI サポート機能
- [Nexus AI Ecosystem](nexus-ai-ecosystem.md) の後続 phase と agentic automation
- `sensor-lab-ios` 自体の参加者向け配布
- Android アプリ、Kotlin Multiplatform、Jetpack Compose への移行

対象外のコードや資料は、保全・検証・将来検討のためにリポジトリへ残せます。存在していることを正式提供の根拠にはしません。

## v1.0 リリース判定

v1.0 は、次の条件をすべて満たした場合にリリース可能と判断します。

1. E0〜E9 の各 Work item が、それぞれの受入条件を満たしている。
2. iOS、Web LP、管理ポータル、admin-api、public-api の責務が本文書の境界と一致している。
3. E9 の自動テストと手動・実機検証、および E8 の本番運用・セキュリティ要件が完了している。
4. OpenAPI、実装、client、テスト、README、関連文書の間に既知の契約不整合がない。
5. hidden beta または対象外の機能が正式な公開導線へ露出していない。

## スコープ変更ルール

v1.0 の包含・除外を変更する場合は、技術的意思決定者の判断を GitHub Issue に記録し、本文書と影響を受ける詳細文書を同じ変更単位で更新します。個別 Issue や既存コードだけを変更して、本文書と矛盾した状態にしません。

[GitHub Issue #7](https://github.com/m0o9l0v3/NexusMobile/issues/7) は iOS 限定と Web LP 方針の決定経緯、Issue #81 は LP の実装詳細として引き続き参照します。
