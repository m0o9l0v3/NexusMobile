# セキュリティメモ

## QRワンタイムログイン（脅威と対策）
- 脅威: QRコードの共有・漏洩による第三者ログイン
  - 対策: QR埋め込みはワンタイムコードのみ、コードはHMACでハッシュ化してDB保存し平文を保持しない。
- 脅威: リプレイ攻撃（同一コードの再利用）
  - 対策: redemption時に未使用かつ期限内のみ許可し、使用済みは即座に無効化する。
- 脅威: 長期間有効なコードの悪用
  - 対策: イベント当日終端（23:59:59 JST）で期限切れとし、短寿命運用を前提にする。
- 脅威: 失敗理由の情報漏えい
  - 対策: redemption失敗時は `invalid_or_expired` に統一して返す。

## JWT失効（revocation）設計と運用
- 目的: JWT漏洩時に即時の止血を可能にし、期限までの悪用を防止する。
- 設計:
  - 発行時に必ず `jti` を付与し、発行済みトークンを `issued_tokens` に記録する。
  - 失効対象は `revoked_jti` に記録し、認証ミドルウェアで `jti` の失効状態を検証する。
  - `revoked_jti` は `expires_at` を保持し、トークン有効期限と同じタイミングで自然失効できる構造にする。
- 運用:
  - 管理者は「ユーザー単位の失効」または「jti指定の失効」をAPIで実行する。
  - 失効理由と実行者IDを記録し、後続の監査やインシデント対応に備える。
