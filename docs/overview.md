# 公開サイト（`web/`）の方針

この文書は `web/` 固有の方針と状況を説明する詳細文書である。v1.0 全体の包含・除外とリリース条件は [Nexus v1.0 スコープ定義](v1.0-scope.md) を正とする。

## 目的（2026-10-25 改訂）

`web/` は、次を掲載する公開サイトとする（[GitHub Issue #131](https://github.com/m0o9l0v3/NexusMobile/issues/131)、2026-10-25 利用者決定）。v1.0 のリリース条件に含める。

- アプリ（iOS）の告知
- 開発状況
- サーバー状況
- 開発に伴う技術説明

v1.0 の参加者向けアプリ機能は iOS アプリに限定する。`web/` は参加者向けアプリの代替ではなく、iOS と機能同期しない。この境界の決定経緯は [GitHub Issue #7](https://github.com/m0o9l0v3/NexusMobile/issues/7) を参照する。

以前の「イベント告知 LP へ再構成する」方針（[GitHub Issue #81](https://github.com/m0o9l0v3/NexusMobile/issues/81)）は、実装されないまま Close されていた。#81 で決めるとしていた事項は #131 へ移した（#81 の 2026-10-25 のコメント）。

## 現在の状況

方針転換前の参加者向け PWA（Home / Map / Events、地図、AI サポート、ログ送信）は 2026-10-25 に削除した。現在の `web/` は、Vite・React・Tailwind の構成と、準備中であることだけを示す1ページである。旧 PWA は git 履歴から参照できる。

## 決まっていること（2026-10-25 利用者決定、#131）

- **サーバー状況**：メンテナンス予定・障害のお知らせはリポジトリ内のファイルに手で書く。加えて、ブラウザから public-api の `/health` に届くかだけを「応答あり／応答なし」で表示する。版・構成・ホスト名など、攻撃の手掛かりになる情報は出さない。公開サイトのオリジンを public-api の CORS で許可する必要がある（#72）。
- **開発状況**：リポジトリ内のファイルに、読む人向けの言葉で手で書く。Issue 名や未公開の情報をそのまま出さない。
- **公開先**：既存 VPS の Caddy で静的ファイルとして配信する（追加契約なし。配信設定は NexusInfra 側）。
- **QR パラメーター**：`?code=XXXX` は公開サイトの「アプリの告知」へ着地させ、App Store へ案内する。`code` の値は使わず、地点表示などはしない。未知・無効・未指定の値でも同じ案内を表示する。v1.0 の QR は resource link だけに使う（[v1.0 スコープ定義](v1.0-scope.md)）。

- **ページ構成**：トップ＋3ページ。トップはアプリの告知（QR の着地点）、開発状況・サーバー状況・技術説明はそれぞれ別ページにする（1画面1主目的、[デザインルール](design-rules.md)）。Vite のマルチページ（HTML 4枚）で作り、ルーター用のライブラリは入れない。技術説明は、後で記事ごとのページへ広げてよい。
- **技術説明の範囲**：構成要素の役割、データの流れ、採用技術とその理由に加え、主な設計判断を読みやすく要約して載せる（例：通信できなくても地図を描ける理由、版を戻さない配信と保存版、ID の付け方）。次は載せない。
  - ホスト名・IP・ポート・サーバーソフトの版、DB のロール名・権限設定、秘密情報の置き場所
  - 認証まわりの仕組みの細部（JWT 失効の実装、HMAC やハッシュチェーンの鍵の扱い）、rate limit の具体値
  - 来場者の個人を特定できる情報や、細かすぎる位置情報
  - 決まっていない事項、内部の Issue 番号や作業の経緯

- **デザイン（#84 との関係）**：#84 の画面設計は流用しない（#84 は iOS の4タブと各状態の画面設計で、公開サイトのページに対応する画面がない）。見た目の基礎（色・文字・角丸・影）は[デザインルール](design-rules.md)と `web/src/styles/theme.css` に従う。#84 からは、承認後に、アプリの告知ページ用の画面画像（スクリーンショット・紹介画像）だけを使う。

## 決めてから実装すること（#131）

- **API の利用**：`/health` 以外の public-api（`GET /api/events/today` など）を使うか
- **掲載する文章**：アプリの告知・開発状況・技術説明の用意

## 環境変数

- 現在の `web/` のコードは環境変数を参照しない。`/health` の死活表示を実装するときに、public-api の URL を指す環境変数（`VITE_API_BASE_URL` など）を定める。
- Public API の定義は `openapi/public.yaml` を参照する。

## 対象外

- iOS アプリと同等の参加者向け Web アプリの提供
- iOS アプリとの機能同期
- チェックイン、参加者プロフィールの収集・ローカル保持
