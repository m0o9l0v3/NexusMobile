# Phase 0 技術検証計画書（Nexus Sensor Lab）

## 1. 検証目的
- Nexus Sensor Lab を用いて、将来の本番 Nexus で必要となるセンサー取得・前処理・記録フローの技術成立性を確認する。
- Windows 環境での実装準備段階において、実機検証前に仕様・計測項目・記録フォーマットを確定する。
- 後日実施予定の Mac + iPhone 実機検証で、最小の手戻りで評価できるよう検証手順を標準化する。

## 2. 検証対象
- センサーデータ取得機能（取得開始/停止、サンプリング周期、欠損有無）。
- タイムスタンプ整合性（端末時刻基準での連続性、ドリフト傾向）。
- 収集データの保存形式（CSV/JSON 等の構造妥当性、再解析可能性）。
- 基本的な前処理（ノイズ除去、リサンプリング、正規化）の実行可否。
- 記録データを本番 Nexus 側へ移植するためのメタデータ要件。

## 3. 使用端末
### 現在（実装準備）
- Windows PC（開発・ログ確認・手順整備用）。

### 後日（実機検証）
- Mac（データ収集制御・解析補助）。
- iPhone（実センサーデータ取得端末）。

## 4. 検証環境
- 開発フェーズ：Windows ローカル環境で Nexus Sensor Lab の設定・検証スクリプト・記録テンプレートを準備。
- 実機フェーズ：Mac + iPhone の同一ネットワーク環境を基本とし、必要に応じてオフライン時のローカル保存も確認。
- バージョン管理：検証時点のアプリ/設定ファイル/スクリプトのバージョンを記録し、再現性を担保。

## 5. 検証手順
1. **事前準備（Windows）**
   - 検証シナリオ、測定時間、サンプリング条件、出力フォーマットを確定。
   - 記録テンプレート（実行日時、端末情報、設定値、備考欄）を作成。
2. **環境セットアップ（Mac + iPhone）**
   - Nexus Sensor Lab の対象設定を適用。
   - 時刻同期（可能な範囲で NTP 同期）を実施。
3. **ベースライン計測**
   - 静止状態で一定時間データ取得し、ノイズレベルと欠損率を確認。
4. **シナリオ計測**
   - 想定ユースケースに沿った動作パターンで複数回データ取得。
   - 取得失敗時は再試行回数と失敗条件を記録。
5. **データ確認・前処理検証**
   - 形式チェック、欠損チェック、タイムライン連続性チェックを実施。
   - 前処理後データとの差分を比較し、影響を記録。
6. **レビュー**
   - 成功条件への達成可否を判定し、課題一覧と次アクションを整理。

## 6. 記録するデータ
- 実行メタ情報：実施日時、担当者、端末種別、OS バージョン、アプリ/スクリプトバージョン。
- 取得設定：サンプリング周期、取得時間、対象センサー種別、保存形式。
- 生データ：タイムスタンプ付きセンサー値一式。
- 品質指標：欠損率、外れ値件数、ノイズ統計（平均/分散など）。
- 実行ログ：開始/停止時刻、エラー内容、再試行有無、所要時間。
- 備考：手動操作、周辺環境（姿勢・移動状況・通信状態）などの文脈情報。

## 7. 成功条件
- 主要センサーデータが想定サンプリング条件で連続取得できる（重大欠損なし）。
- タイムスタンプ整合性が保たれ、解析可能な時系列データとして成立する。
- 保存データが定義フォーマットに準拠し、再読込・再解析が可能である。
- 前処理パイプラインが実行でき、品質指標が許容範囲内に収まる。
- 本番 Nexus への移植に必要なメタデータ要件が過不足なく整理されている。

## 8. 想定される誤差要因
- 端末時刻ズレや時刻同期不足による時系列ずれ。
- 端末姿勢・保持方法の違いによるセンサー値変動。
- バックグラウンド処理や省電力制御によるサンプリング間隔の揺らぎ。
- 通信状態の変化による記録遅延・欠損。
- 周辺磁気・振動・温度など外部環境要因。

## 9. リスクと対策
- **リスク:** 実機環境差分（Windows準備内容と Mac+iPhone 実行条件の不一致）。  
  **対策:** 設定項目を環境非依存な定義ファイル化し、差分チェックリストを運用。
- **リスク:** データ欠損や異常値が多く評価不能。  
  **対策:** 取得リトライ条件、最小取得時間、再計測基準を事前定義。
- **リスク:** 記録フォーマット変更による解析スクリプト破綻。  
  **対策:** スキーマバージョンを付与し、後方互換ルールを定義。
- **リスク:** 検証結果の再現性不足。  
  **対策:** 実施手順・端末状態・周辺条件をテンプレートで必須記録。

## 10. 本番 Nexus への移植方針
- Phase 0 で確定した **データ項目・時刻基準・フォーマット** を本番 Nexus の取り込み仕様の基準とする。
- 収集処理は「取得層（端末依存）」と「前処理/保存層（共通ロジック）」を分離し、移植時の差分を最小化する。
- 検証ログから抽出した失敗パターンを本番の監視項目（欠損率アラート、時刻ズレ検知）へ反映する。
- Mac + iPhone 実機結果を踏まえて最終的な受け入れ基準（SLO 相当）を設定し、Phase 1 開始条件を明文化する。
