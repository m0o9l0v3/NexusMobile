# Issue #27　探す画面と Map の地点詳細

「探す」と Map の検索パネルは、公開 bundle の地点を同じ規則で検索する。結果の行を選ぶと Map の共通地点詳細が開く。ここで確認したデータは Debug 用の合成例である。正式な地点名・別名・所属・ピン・建物形状の受入には #26 の公開データを使う。

## 検索と地点選択

- 対象は `spots[].name` と `search_aliases`。かなをカタカナに揃え、英字の大小と文字幅を畳み込み、NFC に揃える。前後の空白を落とし、内部の連続空白を半角空白1個にして部分一致で照合する。結果は bundle の公開順を保つ。
- 種別は教室・施設・サービスの3種。「すべて」は種別なし・未知種別も含む。既知種別で絞るとこれらは除かれる。建物・階は同じ版の地図から取り、空白だけの値を除く。結果行と読み上げには、同名の「多目的室」の階、「受付」の建物、「実習室」の種別の違いが現れる。
- 行の `CanonicalSpotID` をそのまま Map へ渡し、詳細・ピン・強調する建物を同じ ID から引く。名称検索は地点 ID と `id_aliases` を参照しない。共通詳細への直接指定は完全一致で、大小文字違い・旧 ID・未知 ID は未掲載になる。未配置の掲載地点は詳細を開いて「場所は未提供」と表示し、ピン・建物強調・カメラ移動を要求しない。[地点 ID の規則](../decisions/E1-3-spot-id-integration.md)
- 地点を選ぶと Map 検索を閉じる。新規案内の開始や既存の目的地変更は行わない。「探す」では選択時に編集を終え、タブ復帰時も検索語・種別・結果・一覧位置を保つ。

## 公開状態と版の扱い

| 取得結果 | 探す・Map 検索での表示 |
| --- | --- |
| 有効な空 bundle の初期表示、または初回公開前の HTTP 404 | 「掲載している地点はありません」。404 は検索条件があっても同じ表示。 |
| 有効な版に一致する地点がない | 「該当する地点はありません」。条件を解除できる。 |
| 取得失敗・原因未確定で参照できる版がない | 通信できる場所での再試行を案内する。 |
| 対応外の版で参照できる版がない | 「アプリの更新が必要です」と App Store での更新を案内する。 |
| 保存済みだが最新と確認できていない | 初期一覧・結果・0件・地点詳細で、版・公開日時・最終確認状態を併記する。 |

「探す」は更新確認の完了通知を受け、初期一覧・検索結果・0件・保存版・失敗画面で、表示を保ったまま確定済みの条件を読み直す。初回ロード前・読込中は進行中の操作を優先する。入力途中の語、フォーカス、未知カテゴリの記録、履歴を維持し、新しい検索が始まれば古い結果を捨てる。同じ検索結果は再代入しない。再読込に失敗しても表示中の一覧・結果・0件・保存版を維持する。既に失敗画面なら新しい失敗理由を表示する。失敗画面の「再試行」だけが取得元に再確認を依頼する。[E2-5 §4.3・§6](../decisions/E2-5-participant-data-delivery-v2.md)

Map の検索・地図・地点詳細は同じ固定版を使う。検索パネルの再試行後、案内・出発地選択・経路要求の途中でなければ Map 全体を版の切替点に進める。版切替による検索の再読込では追加の通信確認を行わない。未検索のパネルは案内文または履歴を出し、保存版ではその上にバナーを表示する。未知 ID と取得失敗の地点詳細にも44 ptの閉じるボタンを設けた。[M1-7](../decisions/M1-scope-and-interim-decisions.md)
