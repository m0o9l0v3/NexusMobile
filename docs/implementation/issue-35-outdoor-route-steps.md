# Issue #35　屋外の簡易ステップ案内

経路要約の「屋外のステップ」を開くと、出発、曲がる地点、到着を進行順に読める。各行の距離は、その指示から次の指示まで歩く距離を表す。部屋が目的地の場合は、屋外区間の最後に建物の入口名と「以降は屋内」を表示する。

## 座標・距離・目印

`BundleRouteSolver` は探索が成功したとき、同じ bundle の目印と `RoutePath` から `ResolvedRoute.outdoorSteps` を生成する。各ステップは経路内の連番、出発／曲がり／到着、頂点の由来、座標、対応するノード、角度、次までの距離を持つ。辺の内部折れ点はノードを持たない。同一点、空経路、屋内だけの経路では一覧を表示しない。

- **曲がり角**　頂点の緯度を φ とし、緯度1°を 111,320 m、経度1°をその `max(cos φ, 0.000001)` 倍として、経度差を東向き x、緯度差を北向き y に変換する。入射方向 u、出射方向 v の角度は `atan2(u.y * v.x - u.x * v.y, u.x * v.x + u.y * v.y) * 180 / π`。右を正、左を負とし、±180°の丸め誤差は +180° にそろえる。キャンパス内の短い線分を対象にした局所平面近似である。
- **分割の基準**　0.5 m 未満の隣接点を除き、角度の絶対値が25°未満なら小さな揺れとして距離をまとめる。25°以上45°未満は「やや右／左」、45°以上150°未満は「右／左へ曲がる」、150°以上は「折り返す」。45°を境にすると検証経路の約48°と90°をともに明確な曲がりとして案内できる。いずれも現地評価前の表示基準で、実測精度を表す値ではない。
- **距離**　逆向きの辺も進行順の座標を使う。同じ屋外辺の配信距離を、両端の平均緯度に投影した線分の長さの比で分け、最後の線分に残額を割り当てる。点が欠ける、または全点が重なる辺も配信距離を直前の指示に加え、そこで向きの計算を切る。全辺が退化しても出発・到着を残す。行の表示は各距離を個別に丸めるため、表示値の和と要約に差が出る場合がある。
- **屋内境界**　連続する屋外歩行辺ごとに出発・到着を作る。入口の屋外側は探索グラフで屋外辺と共有される `outside_node_id`。屋内を経て再び外に出る場合も、出入口のあいだに曲がり角を作ったり、屋内の距離を屋外ステップへ加えたりしない。入口名が不明な場合は室名で代用せず「建物の入口に到着（以降は屋内）」と読む。
- **目印の優先順位**　① `landmark.access_node_id` で接続したノードには、その landmark と同じ ID の公開 Spot 名、② `formal_entrance.outside_node_id` に結び付いた入口名、③名前のある `outdoor_node` の順に採用する。同順位は Feature ID 昇順。入口名は入口 Spot 名を優先し、次に建物名＋入口 Feature 名、建物名だけの順とする。建物名は建物 Spot 名、建物 Feature 名の順で、入口名に含まれる接頭辞は重ねない。空白だけの名称は除く。公開されていない landmark、生 ID、近くの建物や外形から目印を補わない。直進中の目印は「通過」にまとめ、出発・到着や既出の目印を繰り返さない。

## UI と S06 の未決事項

経路要約の屋内注記の下、操作ボタンの上に初期状態で閉じた一覧を配置した。標準文字サイズでは収まる場合は全行を並べ、長い一覧は最大220 ptの範囲でスクロールする。アクセシビリティ文字サイズでは行を縦積みにして要約全体のスクロールを使う。開閉状態はシーン内の経路要求 ID に結び付けているため、要約のレイアウトが切り替わっても同じ経路の状態を読み、新しい経路は閉じて表示する。

トグルは44 pt以上の操作領域を持ち、Reduce Motion 時は開閉アニメーションを止める。VoiceOver は開閉状態と件数、各行は番号・指示・距離・目印を1要素で読む。Map・地点詳細・共有部品の変更はない。既存のコントラスト試験が `Surface` 上の本文・補足文字、`Surface` およびその上の `tintSurface` 上のアクセント色、`CautionAccent` 上の `OnAccent` をライト／ダーク双方で検証している。

S06 のレビューでは、カード内一覧を続けるか専用画面で1件ずつ示すかを比較する。手動の「次へ／前へ／終了」を採用する場合は、最初と最後の操作、終了後の戻り先、地図を全体表示に保つか選択ステップへ移すかを対象版・node ID・承認者・承認日とともに記録する。今回の「案内を終了」は #34 の既存操作。現在ステップの選択、自動送り、別画面遷移、連続音声案内は未承認である。

## シミュレーターでの画面確認

修正前に、親セッションが iPhone 17 Pro（iOS 26.5）シミュレーターで `RouteCheckFixtures` を使って経路要約を確認した。

| 経路 | 確認した表示・操作 |
| --- | --- |
| `found` | ライト／ダークで一覧を折りたたみ、展開した。展開時、歩行アイコンの円だけが細く、1行目の番号の開始位置が他の行とずれていた。また、番号がタイトルより下に見えた。 |
| `indoor` | AX5 で一覧を展開し、縦積みのステップをスクロールできた。 |
| `samePoint` | 同一点の経路要約にはステップ欄が表示されなかった。 |

この確認を受け、方向アイコンの枠を最小28 × 28 ptにそろえた。通常文字サイズでは番号・タイトル・距離を最初の行のベースラインにそろえ、AX サイズでは縦積みを維持した。
