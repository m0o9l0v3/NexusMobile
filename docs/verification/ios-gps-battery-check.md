# iOS 位置情報の精度と電池の実機確認（#80）

[#80](https://github.com/m0o9l0v3/NexusMobile/issues/80)（E9-6）を、オーナーが1人で、実機の iPhone を持って構内を歩けば終わるようにまとめた手順書です。
対象は `apps/nexus-ios/` の現在地の取得（#29、PR [#185](https://github.com/m0o9l0v3/NexusMobile/pull/185)）と位置情報の権限（#25、PR [#184](https://github.com/m0o9l0v3/NexusMobile/pull/184)）です。

#80 の工程3で足された条件に合わせ、**端末・移動経路・測定時間・取得間隔・精度/鮮度・電池の条件・判定基準**を記録し、**仮説 → 計測 → 採用値**を残します。
採用値は #85（Map 画面と地点詳細の実装）の公開受入へ反映します。最終の測定の完了は #84（デザイン）の開始条件にしません。

この文書は手順と記録の型だけです。**結果はまだありません**（末尾の「実施記録」に追記します）。

## 0. 守ること

- **位置は端末の外へ出さない。** 記録用の機能（`-NexusLocationLog`）は端末の中のファイルに書くだけで、通信しません。Info.plist と説明シートの約束「現在地は Nexus のサーバーへ送りません」を守ります。
- **公開する記録に座標を書かない。** 経路は建物名だけで書きます。記録ファイルにも緯度・経度は入れていません（`LocationFixLogTests.testLineNeverContainsCoordinates`）。画面の写真を Issue に貼るときは、地図が写っていても構いませんが、座標の数字が写るもの（ほかのアプリの画面など）は貼りません。
- 記録用の機能は **DEBUG ビルドだけ**にあります（`#if DEBUG`）。Release（TestFlight・App Store）には入りません。

## 1. 目的と、確かめる仮説

仮の値はすべて `LocationAcquisitionSettings.provisional`（`apps/nexus-ios/Nexus/Features/Location/Models/CurrentLocationModels.swift`）の1か所にあります。

| ID | 値 | 仮の値 | 仮説（なぜこの値か） | 測るもの |
|---|---|---|---|---|
| H-1 | 使う点の誤差の上限 `maximumHorizontalAccuracy` | 50 m | 屋外の構内では、ほとんどの点が誤差 50 m 以内で届く。50 m を超える点は青い点を別の建物の側に出してしまうので使わない | 区間ごとの誤差（`horizontal_accuracy_m`）の中央値・95%値、使える点の割合 |
| H-2 | 最初の点の待ち時間 `acquisitionTimeout` | 15 秒 | 屋外なら、現在地ボタンを押してから 15 秒以内に使える点が届く。15 秒待っても来なければ、待たせるより「現在地を取得できません」を出したほうがよい | ボタンを押してから最初の使える点までの秒数（`start` 行 → 最初の `usable=1` の `fix` 行） |
| H-3 | 点を動かす最短間隔 `minimumUpdateInterval` | 1 秒 | 歩いているとき OS はおよそ1秒ごとに点を出す。1 秒で間引けば、青い点はなめらかに動き、描き直しも増えすぎない。この値は描き直しを減らすだけで、GPS の電池は変わらない | 点の間隔（`interval_s`）の中央値、見た目のなめらかさ |
| H-4 | 鮮度（点の古さ） | 値なし（今は判定に使っていない） | 歩いているときに届く点は新しい（届いた時刻と点の時刻の差が 1 秒前後）。古い点を捨てる条件はいらない | 点の古さ（`age_s`）の中央値・95%値 |
| H-5 | OS に伝える使い方 `activity` | `.otherNavigation` | 徒歩の案内に合う。`.fitness` や `.default` より、歩いているときの点が新しく、精度もよい | 同じ区間を `.otherNavigation` と `.fitness` で歩いたときの H-1・H-4 の差（任意） |
| H-6 | 構内の余白 `campusMarginMeters` | 100 m | 構内の端（門・駐車場）に立っている人でも、屋外の GPS 誤差（数十 m）で「構内から離れています」が出ない幅 | 構内の端での誤差の最大値・95%値 |
| H-7 | 電池 | 値なし | 位置を取るのは Map を表示していて現在地ボタンを押した後だけ。Map を離れる・背面に回ると止まる。取得中に増える電池の減りは、画面を点けているだけの減りより小さい | 30 分あたりの電池の減り（取得あり／なし）、Map を離れたときに位置情報の利用表示が消えるか |

あわせて、#184 で実機に回した**権限のダイアログ**（手順 6.1）を確かめます。

## 2. 端末

オーナーの手持ちの iPhone を使います。何台・どの機種かは記録表に書きます。

- **最低1台**：最新の iOS（26 以降）。参加者の多くが使う iOS で、#80 の判定はこの端末で行う。
- **もう1台あれば**：古めの機種、または Deployment Target の iOS 18。GPS の性能と電池の古さで結果が変わるかを見る（判定は1台目、2台目は参考）。
- 電池の確認は、**「設定」→「バッテリー」→「バッテリーの状態」の最大容量**を記録します（古い電池は減りが速い）。
- シミュレーターでは GPS も電池も測れません。必ず実機です。

## 3. 準備（Mac で1回）

### 3.1 DEBUG ビルドを入れる

1. iPhone を Mac につなぎ、Xcode で `apps/nexus-ios/Nexus.xcodeproj` を開く。Scheme は `Nexus`、Run の Build Configuration は **Debug** のまま（記録用の機能は Debug にしかない）。
2. 実行先に iPhone を選び、Run で入れる。初回は iPhone の「設定」→「一般」→「VPN とデバイス管理」で開発元を信頼し、「プライバシーとセキュリティ」→「デベロッパモード」をオンにする。
3. 端末の識別子を控える。

```bash
xcrun devicectl list devices
```

### 3.2 起動のしかた

本番の Map は構内の地図データが届くまで「未提供」の表示で、現在地ボタンが出ません。確認では DEBUG の起動引数で、検証用の14棟（`-NexusMapKitCheck`）の Map を直接開きます。
**位置はフィクスチャではなく、本物の Core Location** です（`-NexusLocationFixture` は付けない）。

起動引数はホーム画面のアイコンから開くと付きません。毎回 Mac から起動します。
電池を測るときはケーブルで充電されないよう、起動したらケーブルを抜きます（`devicectl` で起動したアプリはデバッガーにつながっていないので、抜いても動き続けます）。

```bash
xcrun devicectl device process launch --device <端末の識別子> --terminate-existing jp.nexus-app.mobile -NexusMapKitCheck -NexusPreviewScreen map -NexusLocationLog
```

| 起動引数 | 意味 |
|---|---|
| `-NexusMapKitCheck` | 検証用の14棟を MapKit で描く。建物の名前は本物だが、**形と配置は格子状の仮のもの**。下に見える Apple の地図（道・建物）は本物なので、青い点の正しさは Apple の地図で見る |
| `-NexusPreviewScreen map` | Map タブで開く |
| `-NexusLocationLog` | 届いた点を端末内の CSV に書く（4章） |
| `-NexusLocationActivity <default\|otherNavigation\|fitness>` | H-5 の比較用。使い方を変える |
| `-NexusLocationMaxAccuracy <メートル>` | H-1 の比較用。誤差の上限を変える |
| `-NexusLocationTimeout <秒>` | H-2 の比較用。待ち時間を変える |
| `-NexusLocationMinInterval <秒>` | H-3 の比較用。間引きの間隔を変える |

値を変える引数を付けなければ、仮の値（`provisional`）のままです。読めない値は無視されます。

**注意：検証用の14棟は本物の構内の位置にありません。** そのため、構内にいても「構内から離れています」が出て、カメラが検証用の14棟に残ることがあります。これは今回の判定に使いません（H-6 は記録ファイルの誤差で判定し、「構内から離れています」の表示の確かめは本物の地図データが入った後、#85 で行います）。追従のカメラを見たいときは、表示が出たら地図を自分で現在地へ動かします。

## 4. 記録ファイル（`-NexusLocationLog`）

### 4.1 中身

起動ごとに `Documents/NexusLocationLog/location-<日時>.csv` が1つでき、知らせが届くたびに1行増えます。書くのは `CurrentLocationStore` が受け取る前の知らせで、アプリの振る舞いは変えません。

| 列 | 意味 |
|---|---|
| `received_at` | アプリが受け取った時刻（端末の時刻、時差付き） |
| `event` | `start`（取得開始）／`fix`（点）／`unavailable`（OS が一時的に位置を出せない）／`ended`（配信が終わった）／`stop`（取得をやめた：Map を離れた・背面・失敗） |
| `horizontal_accuracy_m` | 点の水平の誤差（m、半径）。`fix` だけ |
| `age_s` | 点の古さ（受け取った時刻 − 点の時刻、秒） |
| `interval_s` | 1つ前の点との間隔（秒、点の時刻どうし）。取得を始めて最初の点は空 |
| `usable` | 誤差がそのときの上限以内なら 1（青い点に使う候補）。間隔の間引きはここでは考えない |
| `battery_percent` | 電池の残り（%）。iOS が 5% 刻みでしか返さないことがあるので、電池の判定は「設定」の値も見る |
| `low_power_mode` | 低電力モードなら 1 |
| `settings` | `start` 行だけ。そのときの値（使い方・待ち時間・誤差の上限・間隔・余白） |

「正確な位置情報」がオフのときの点（おおよその位置）は、アプリが使わないので記録にも出ません。

### 4.2 取り出し

アプリを消すとファイルも消えます。**入れ直す前に必ず取り出します**（権限の確認の手順 6.1 で入れ直すため）。

```bash
xcrun devicectl device copy from --device <端末の識別子> --domain-type appDataContainer --domain-identifier jp.nexus-app.mobile --source Documents/NexusLocationLog --destination ./gps-logs
```

Local.xcconfig で Bundle ID を上書きしているときは、上の2つのコマンドの `jp.nexus-app.mobile` をその ID に読み替えます。

Xcode の「Window」→「Devices and Simulators」→ Nexus →「…」→「Download Container…」でも取り出せます（中の `AppData/Documents/NexusLocationLog/`）。

取り出した CSV は**リポジトリにコミットしません**。座標は入っていませんが、時刻と区間の組み合わせで歩いた様子が分かるためです。結果は7章の表に数字だけ写します。

### 4.3 集計

CSV を区間ごとに分けたいときは、6.2 で控えた区間の開始・終了の時刻で切ります。次のスクリプトは、1つの CSV（または時刻で切った範囲）の誤差・古さ・間隔の中央値と95%値、使える点の割合、最初の使える点までの秒数を出します。

```bash
python3 - gps-logs/location-<日時>.csv <開始 HH:MM:SS> <終了 HH:MM:SS> <<'EOF'
import csv, sys, statistics
from datetime import datetime
path = sys.argv[1]
start = sys.argv[2] if len(sys.argv) > 2 else None
end = sys.argv[3] if len(sys.argv) > 3 else None
rows = list(csv.DictReader(open(path, encoding="utf-8")))
def clock(r): return datetime.fromisoformat(r["received_at"]).strftime("%H:%M:%S")
rows = [r for r in rows if (not start or clock(r) >= start) and (not end or clock(r) <= end)]
fixes = [r for r in rows if r["event"] == "fix"]
def q(values, p):
    values = sorted(values)
    return values[min(len(values) - 1, int(round(p * (len(values) - 1))))] if values else None
for column in ["horizontal_accuracy_m", "age_s", "interval_s"]:
    values = [float(r[column]) for r in fixes if r[column]]
    print(f"{column}: n={len(values)} median={statistics.median(values) if values else None} p95={q(values, 0.95)} max={max(values) if values else None}")
usable = [r for r in fixes if r["usable"] == "1"]
print(f"usable: {len(usable)}/{len(fixes)} = {len(usable) / len(fixes):.0%}" if fixes else "usable: no fixes")
print("unavailable:", sum(r["event"] == "unavailable" for r in rows), "ended:", sum(r["event"] == "ended" for r in rows))
first = None
for r in rows:
    if r["event"] == "start": first = datetime.fromisoformat(r["received_at"])
    elif r["event"] == "fix" and r["usable"] == "1" and first:
        print("time to first usable fix (s):", round((datetime.fromisoformat(r["received_at"]) - first).total_seconds(), 1))
        first = None
battery = [int(r["battery_percent"]) for r in rows if r["battery_percent"]]
if battery: print("battery %:", battery[0], "->", battery[-1])
EOF
```

## 5. 経路と条件

### 5.1 経路（屋外の区間）

建物名だけで書きます。**座標・地図の切り抜き・道の細かな説明は公開しません。**
建物の並びは実際の構内に合わせてオーナーが組み替えて構いません。そのときは記録表の「区間」に、実際に歩いた順の建物名を書きます。

| 区間 | 歩くところ（屋外） | ねらい |
|---|---|---|
| R1 | 構内の入口（門）→ 管理棟 | 来場者が最初に使う区間。構内の端（H-6） |
| R2 | 管理棟 → 教室棟 → 実習棟 | 中心の通路。基本の値（H-1〜H-4） |
| R3 | 実習棟 → 格納庫A → 格納庫B | 大きな建物の脇・開けた場所 |
| R4 | Da Vinci Hall → CTC → CTC2 | 建物どうしが近い区間（建物の陰で誤差が増えるか） |
| R5 | アリーナ → 食堂 → 男子寮・女子寮の前 | 端の側の区間 |
| E1〜E3 | 構内の端（門・駐車場など）3か所で、それぞれ 2 分立ち止まる | H-6（構内の余白） |

- 各区間は**ふつうの歩く速さ**で、1区間 2〜5 分を目安にします。
- 屋内は判定に使いません（GPS はもともと屋内で弱い）。屋内に入ったときの振る舞いは「観察」欄に書くだけにします。
- 区間の**開始と終了の時刻**を記録表に書きます（4.3 の集計で使う）。iPhone の時計で分・秒まで見ます。

### 5.2 条件（どの回も記録する）

| 項目 | 決め方 |
|---|---|
| 天気 | 晴れ・くもり・雨 |
| 開始時の電池 | **80〜100%** から始める（電池が少ないと iOS の振る舞いが変わる）。「設定」→「バッテリー」の値 |
| 低電力モード | 基本は**オフ**。H-7 の追加の回だけオン |
| 画面 | **点けたまま**。「設定」→「画面表示と明るさ」→「自動ロック」を「なし」、明るさは**手動で半分**に固定し、「自動調節」をオフ（「アクセシビリティ」→「画面表示とテキストサイズ」） |
| ほかのアプリ | 開始前にすべて終了する。機内モードはオフ、Wi-Fi・Bluetooth はふだんどおり**オン**（参加者の多くの状態。Wi-Fi は位置の精度にも効く） |
| 充電 | **ケーブルを抜く**。モバイルバッテリーもつながない |
| 画面を消したとき | アプリは背面に回ると取得を止める設計なので、画面を消した状態の電池は測りません。代わりに H-7 で「止まること」を確かめます |

## 6. 手順

順番に進めれば、1日（半日ほど）で終わります。所要時間は目安です。

### 6.1 権限のダイアログ（約 30 分、#184 で実機に回したもの）

アプリを消して入れ直すと、Nexus の位置情報の権限は最初の状態に戻ります。**入れ直す前に 4.2 で記録ファイルを取り出します。**
各項目の前にアプリを消し、Xcode の Run で入れ直してから、3.2 の起動のしかたで開きます（`-NexusLocationLog` はあってもなくてもよい）。

| ID | やること | 期待する結果 |
|---|---|---|
| P-1 | Map で現在地ボタンを押す → 説明シート「現在地を使いますか？」で「位置情報を使う」 | 説明シートのあとに **iOS のダイアログが本当に出る**。文言が Info.plist の `NSLocationWhenInUseUsageDescription`（「…現在地は Nexus のサーバーへ送りません。」）と同じ。選択肢に「1回だけ許可」「Appの使用中は許可」「許可しない」がある。「常に許可」は無い |
| P-2 | P-1 のダイアログで「**1回だけ許可**」 | 青い点が出る。ホームに戻ってしばらく（1分ほど）置き、アプリを開き直して（または終了して 3.2 で起動し直して）もう一度ボタンを押すと、**もう一度尋ねられる**（説明シートか iOS のダイアログ）。古い青い点が残っていない。落ちない |
| P-3 | P-1 のダイアログで「許可しない」 | 「位置情報が許可されていません」の表示と「設定を開く」「出発地を自分で選ぶ」。「設定を開く」で Nexus の設定画面が開く |
| P-4 | P-1 のダイアログで、左上の「**正確な位置情報**」を**オフ**にしてから「Appの使用中は許可」 | すぐに **一時的に正確な位置情報を求めるダイアログ**が出る。文言が `NSLocationTemporaryUsageDescriptionDictionary` の `CurrentLocation`（「構内の地図で現在地を正しい位置に表示し、経路案内の出発地に使うため、正確な位置情報を一時的に使います。…」）と同じ |
| P-5 | P-4 の一時的なダイアログで「**1回だけ許可**」（正確な位置を一時的に許可） | 青い点が出る（記録ファイルに `fix` が出る）。ホームに戻ってしばらく置き、戻ってボタンを押すと、**一時的なダイアログがもう一度出る**（一時的な許可は使い終わると切れる） |
| P-6 | P-4 の一時的なダイアログで「**許可しない**」 | 「位置の精度が足りません」の表示（「設定を開く」「出発地を自分で選ぶ」）。青い点は出ない |
| P-7 | 「Appの使用中は許可」・正確な位置オンで追従中に、「設定」→ Nexus →「位置情報」→「正確な位置情報」をオフにして戻る | 取得が止まり、青い点が消える。もう一度ボタンを押すと一時的なダイアログ（P-4）が出る |
| P-8 | 「設定」→「プライバシーとセキュリティ」→「位置情報サービス」を全体でオフにしてからボタン | 「位置情報サービスがオフです」の表示。「設定を開く」が出る |
| P-9 | P-1 の説明シートで「後で」 | iOS のダイアログは出ない。もう一度ボタンを押すと説明シートが出る |

P-2・P-5 の「しばらく置く」の長さは iOS が決めます。もう一度尋ねられなかったら、置いた時間を書いて、アプリを終了（App スイッチャーで上へ払う）してから試します。

### 6.2 精度と鮮度（H-1〜H-6、約 2 時間）

1. 権限を「Appの使用中は許可」・正確な位置オンにしておく（6.1 の後なら P-7 を戻す）。
2. 5.2 の条件にそろえ、条件を記録表に書く。
3. R1 の始めの場所で、3.2 の起動のしかた（仮の値のまま）で開き、ケーブルを抜く。
4. **最初の点（H-2）**：現在地ボタンを押し、青い点が出るまでの秒数を記録表に書く（記録ファイルからも分かる）。15 秒で「現在地を取得できません」になったら「失敗」と書き、「もう一度試す」を押す。
5. 歩き始める時刻を書き、R1 を歩く。歩きながら見ること：
   - 青い点が**下の Apple の地図で自分のいる側**に出ているか（道のどちら側か、どの建物の前か）。
   - 点がなめらかに動くか、跳ぶか、止まるか（H-3）。
   - 「構内から離れています」が出たら時刻を書く（3.2 の注意のとおり判定には使わない）。
6. 区間の終わりの時刻を書く。R2〜R5 も同じ。
7. **構内の端（H-6）**：E1〜E3 でそれぞれ 2 分立ち止まり、開始・終了の時刻を書く。
8. **最初の点の繰り返し（H-2）**：**`-NexusLocationTimeout 60` を付けて起動し直してから**行う。仮の 15 秒のままだと、15 秒で取得を止める（`CurrentLocationStore` が `updates.stop()` を呼ぶ）ので、15 秒を超えて届いた点は画面にも記録にも残らず、何秒かかったかが分からないため。

## 8. 判定基準

判定は「合格」「不合格」「保留（条件をそろえて取り直す）」の3つです。判定は2章の1台目（最新の iOS）で行います。

| ID | 合格 | 不合格のときの扱い |
|---|---|---|
| H-1 誤差の上限 50 m | R1〜R5 の**すべて**で、使える点の割合が **90% 以上**。かつ、使える点で青い点が自分のいる側（道のどちら側・どの建物の前）に出ている | 誤差の95%値が 50 m を超える区間がある → 9章の手順で上限を見直す。50 m 以内の点でも明らかに別の側に出る → 上限を下げる |
| H-2 待ち時間 15 秒 | `-NexusLocationTimeout 60` で実測した秒数（7.4）で、温まった状態の 10 回のうち **9 回以上**が 15 秒以内。冷えた状態の 3 回は**すべて** 15 秒以内 | 冷えた状態で 15 秒を超える → 待ち時間を「冷えた状態の実測の最大 + 5 秒」（上限 30 秒）へ延ばし、その値を `-NexusLocationTimeout` に付けて冷えた状態をもう3回とり、すべてその時間内に出ることを確かめてから採用する。60 秒超が出た → 30 秒に延ばしても足りないので、待ち時間は 30 秒にし、取得できないときの案内（「出発地を自分で選ぶ」）で受けることを #85 で決める |
| H-3 間隔 1 秒 | 歩いているときの間隔の中央値が **2 秒以下**で、点が止まって見えない・跳ばない | 中央値が 2 秒を超える → 間隔は変えず、H-5 の使い方を見直す（間隔は OS の配信より短くしても意味がない） |
| H-4 鮮度 | 歩いているときの古さの中央値が **1.5 秒以下**、95%値が **5 秒以下** | 95%値が 5 秒を超える → 古い点を捨てる条件（新しい値）を足すか #85 で決める |
| H-5 使い方 | `.otherNavigation` の誤差・古さが `.fitness` と同じか、よい（任意。比べなければ `.otherNavigation` のまま） | `.fitness` のほうが明らかによい（95%値で 10 m 以上、または古さの中央値で 1 秒以上） → `.fitness` に変える |
| H-6 余白 100 m | E1〜E3 の誤差の**最大値が 100 m 以下**、95%値が **50 m 以下** | 最大値が 100 m を超える → 余白を「最大値を 10 m 単位で切り上げた値」に広げる。「構内から離れています」の表示そのものは、本物の地図データで #85 のときに確かめる |
