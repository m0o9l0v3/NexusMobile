# E1-5: 座標系・測地系を確定する

- 移行元ID: E1-5 / 区分: E1
- 依存: E1-4（`docs/decisions/E1-4-geojson-schema.md`）
- 判断日: 2026-09-10
- 判断者: リポジトリオーナー（技術的意思決定者）
- 状態: 採用

## 採用方針

公開する MapDataset の全 geometry は、E1-4 で確定した RFC 7946 準拠の WGS 84（OGC CRS84）2次元座標とする。position の順序は常に `[longitude, latitude]`、単位は10進度とし、GeoJSON の `crs` メンバーと高度の第3要素は使用しない。

屋内の測量・SVG制作・ノード配置では、フロアごとの右手系2次元ローカル座標を入力正本として持つ。単位はメートル、`x_m` はフロア図の右方向、`y_m` はフロア図の上方向を正とする。SVGのY軸は下向きなので、SVG座標へ描画するときだけY方向を反転し、測量座標自体の符号を変えない。

屋内ローカル座標から公開用WGS 84座標への変換は、フロア単位の2次元相似変換とする。WGS 84のアンカー座標を基準点周りの局所接平面 East-North-Up（ENU）へ変換し、ローカルXYからENUのEast/Northへ平行移動・回転・一様縮尺を適用した後、WGS 84へ戻す。

```text
floor-local (x_m, y_m)
  -> 2D similarity transform
local ENU (east_m, north_m)
  -> inverse topocentric conversion
WGS 84 (longitude, latitude)
  -> RFC 7946 GeoJSON
```

2次元相似変換は次式で表す。

```text
east_m  = tx_m + scale * ( cos(theta) * x_m - sin(theta) * y_m )
north_m = ty_m + scale * ( sin(theta) * x_m + cos(theta) * y_m )
```

中間計算は倍精度浮動小数点で行い、途中では丸めない。GeoJSONへ書き出す longitude / latitude は小数6桁に丸める。変換実装は同じ入力、アンカー、パラメータから同じ結果を生成しなければならない。

## アンカー契約

実アンカーは #36 で公開対象フロアとcanonical SVGを確定した後、フロアごとに選定・実測・承認する。E1-5では、後続Issueが使用する入力契約と合格条件を確定する。

各フロアは最低4点を持つ。

- 変換パラメータの推定に使う `fit` アンカーを3点以上。
- 推定に使わない独立した `check` アンカーを1点以上。
- アンカーは同一直線上へ偏らせず、対象フロアの範囲を囲むよう、互いにできるだけ離れた恒久的な構造点を選ぶ。
- 入口中心、建物角、柱芯など、現地とフロア図の同一点を再特定できる場所を使う。部屋名、可動家具、塗装のみの印、GPS画面上の曖昧な地点名は単独のアンカーにしない。
- 同じ物理点について、フロアローカル座標とWGS 84座標の両方が揃っていない記録はアンカーとして扱わない。
- `fit` と `check` を同じ点で兼用しない。

アンカー入力は、少なくとも次の項目を保持する。

| 項目 | 必須 | 規則 |
|---|---|---|
| `anchor_id` | 必須 | フロア内で一意かつ再利用しないID |
| `building_id` | 必須 | E1-1で確定したcanonical building ID |
| `floor_id` | 必須 | E1-2で確定したcanonical floor ID |
| `role` | 必須 | `fit` または `check` |
| `local_x_m`, `local_y_m` | 必須 | canonical floor-local座標、メートル |
| `longitude`, `latitude` | 必須 | WGS 84（OGC CRS84）の10進度 |
| `point_description` | 必須 | 現地と図面で同一点を再特定できる説明 |
| `source_file`, `source_location` | 必須 | 原本ファイル名とシート・行・地物ID等 |
| `measurement_method` | 必須 | GNSS、トータルステーション、既知点からの測距等 |
| `measured_at`, `measured_by` | 必須 | 測定日時と測定者 |
| `reported_accuracy_m` | 必須 | 測定機器・方法が示す水平精度。不明は空欄でなく `unknown` と明記 |
| `approved_at`, `approved_by` | 必須 | 公開用アンカーとしての承認記録 |

基準点のWGS 84座標、高さ0mを局所接平面の原点として保持する。v1.0は水平2次元のみを扱うため、高さは変換計算の固定値であり、GeoJSONへ出力しない。

## 合格条件と許容誤差

許容値は実測結果を見る前に次のとおり固定する。

1. ローカル座標をWGS 84へ変換し、同じ確定パラメータでローカル座標へ戻した数値往復誤差は、水平距離で各点 `0.05 m` 以下。
2. `fit` アンカーの位置残差は、水平RMS `2.0 m` 以下かつ各点 `3.0 m` 以下。
3. 変換推定に使わない各 `check` アンカーの位置合わせ誤差は、水平距離で `3.0 m` 以下。
4. longitude / latitude を小数6桁へ丸めた後に逆変換した追加誤差は、丸め前から水平距離で `0.10 m` 以下。
5. 上記の値は、距度をそのまま平面距離として比較せず、同じ局所ENU上のメートル単位で計算する。

1点でも上限を超えた場合、アンカーの入れ替え、測定方法の確認、再測定を行う。外れ値を無言で除外したり、平均化して合格にしたり、相似変換をアフィン変換へ変更して吸収したりしない。除外する場合は、対象、理由、承認者を記録してから変換パラメータを再生成する。

## 入力と成果物の分離

原本のGeoJSON、実測Excel、GPS記録は変更しない。後続の変換処理は次を分離して保持する。

1. 原本と原本内の行・地物を指す追跡情報。
2. canonical IDへの対応表。
3. floor-local座標とアンカー入力。
4. アンカーから決定的に算出した変換パラメータ。
5. WGS 84へ変換したMapDataset geometry。
6. fit残差、check誤差、数値往復誤差、丸め誤差を含む検証結果。

入力座標系、軸順、単位、測定方法のいずれかが不明な値は推定変換しない。`EPSG:4326` のライブラリ表現が緯度・経度順であっても、GeoJSONへ格納するときは必ず `[longitude, latitude]` に正規化する。

## 採用理由

- 公開データをRFC 7946の単一座標契約に揃え、QGIS、API、iOSで独自CRSの解釈を不要にできる。
- 屋内編集をメートル単位に保つことで、廊下長、入口、ノード、経路距離を度単位で扱わずに済む。
- 局所ENUを介することで、経度と緯度の度数差を同じ長さとして扱う誤りを避けられる。
- 相似変換は距離比と角度を保ち、図面の形を変えずに位置、方位、縮尺を合わせられる。
- 推定用と独立検証用のアンカーを分けることで、使用した点だけに過適合した変換を公開前に検出できる。
- 原本、対応表、変換、検証を分けることで、再測定時に履歴を失わず再生成できる。

## 却下した選択肢

- **屋内ローカル座標をGeoJSONのcoordinatesへ直接格納する**: RFC 7946 readerがWGS 84と解釈し、誤った場所へ描画するため却下。
- **GeoJSONの`crs`メンバーでローカル座標を識別する**: RFC 7946で廃止された契約となり、標準readerとの相互運用性を失うため却下。
- **緯度・経度の差へ直接XY変換を適用する**: 経度1度と緯度1度の距離が異なり、緯度にも依存するため却下。
- **1点アンカーと目視方位だけで配置する**: 回転と縮尺を独立検証できず、現在のGPS原本にも目視・コンパス記録が含まれるため却下。
- **2点だけで変換を確定する**: 2点へ常に一致しても第三点の誤差を検出できないため却下。
- **一般アフィン変換または射影変換を使う**: せん断や軸別縮尺で測定・図面の不整合を隠し、距離と角度を変えるため却下。
- **Web Mercatorを変換計算の正本にする**: 表示用投影であり、floor-local測量とWGS 84の基準契約として固定する必要がないため却下。
- **GPS精度が不明な記録を自動的に3m精度とみなす**: 原本にない精度を推定することになるため却下。
- **小数桁を原本の見た目どおり無制限に保持する**: 測定精度を超えた見かけの精度を公開データへ持ち込むため却下。

## 現時点の入力資料に対する判断

`Nexus GPS実測記録 20260719.xlsx` には屋外のWGS 84座標があるが、`mb` / `ptb` の建物基準点は未入力である。`mb` 昇降口のWGS 84座標は1点ある一方、対応するfloor-local座標がなく、`入口データ`も未測定である。廊下長はfloor-localデータ作成の材料になるが、アンカーの代替にはならない。

したがって、現時点の原本から実アンカーや変換パラメータを推定しない。実アンカーの選定・測定・位置合わせ検証は、公開対象フロアとcanonical SVGを先に確定できる #36 の完了条件へ移す。

## 本Issueの完了境界

E1-5は、公開座標、floor-local座標、変換方式、アンカー入力契約、丸め、許容誤差、異常時の扱いを決定した時点で完了とする。実アンカー値とフロア別変換パラメータは #36 の成果物であり、本Issueの完了を待たせない。
