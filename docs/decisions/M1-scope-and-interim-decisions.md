# M1: 正式データによる地点表示の範囲と暫定判断

- 区分: マイルストーン M1（v1.0 の中間到達点）
- 状態: **起案**（2026-10-23、技術的意思決定者の判断をもとに作成。本書のマージをもって採用とする）
- 前提の決定: [E2-5](E2-5-participant-data-delivery-v2.md)（配信契約 v2）、[E1-4 改訂1](E1-4-r1-destination-features.md)、[E1-7](E1-7-room-canonical-ids.md)、[E1-3](E1-3-spot-id-integration.md)、NexusStudio #4（公開・復旧の Studio への一本化）
- 関連 Issue: #23、#109、#24、#26、#85、#84、#31、#28、#21、NexusStudio#11、NexusInfra#8・#17

本書は M1 の受入範囲と、上位の Issue で正式に決まるまでの暫定判断を記録する。E2-5 などの採用済み契約は変えない。

## 1. M1 の到達目標

Studio で公開した正式な地点情報が、安全で整合した単一の版として iOS に届き、Map 上で正しい地点として選択・閲覧できること。

経路探索（M2）、屋内外・階層間の案内（M3）、実機統合試験・TestFlight（M4）は M1 に含めない。v1.0 の必須範囲から外すという意味ではない。

## 2. 決定事項

| ID | 論点 | 結論 | 関係先 |
|---|---|---|---|
| M1-1 | 受入で表示を求める地点の範囲 | **14棟の建物 Spot は全件の表示を必須とする。** 部屋・ランドマークは、Studio で公開したものがすべて正しい位置・ID で表示されることだけを求め、件数は受入条件にしない | #16、#26、#85 |
| M1-2 | `delivery` スキーマの置き場所と public-api の接続 | **`studio`・`delivery` とも PG17 の `nexus` データベースに置く。** public-api は既存の `nexus_public` 接続のまま、`delivery` の2表だけを SELECT する（スキーマの USAGE と2表の SELECT を付与）。接続文字列は増やさない。admin の移行履歴（2本）は変わらない。E2-5 §3.1 の前提と一致する | NexusInfra#8・#17、#23 |
| M1-3 | iOS の配信 API の接続先の注入 | **ビルド構成ごとの xcconfig に `NEXUS_API_BASE_URL` を置き、Info.plist 経由で読む。** 値が空なら従来どおり「未接続」で起動する。秘密情報は置かない | #109 |
| M1-4 | M1 の実データ（GeoJSON 2.0.0）を Studio に入れる経路 | **レビュー済みの GeoJSON を取り込みの管理コマンド（または API）で投入し、Validator を通してから Release で公開する。** Map Editor の目的地 Feature の追加・移動（ME-16・ME-17）の画面は、Figma Phase 2 の後に回す | NexusStudio#11 |
| M1-5 | 地図の描画方式 | **SwiftUI の MapKit（`Map`・`MapPolygon`・`Annotation`）を前提に進める。** 外部 SDK は追加しない。#24 の「外部タイル不通でも構内図を表示できる」条件は、通信断で建物の形・ラベル・ピンが表示されることの確認として #24 で検証・記録する（§3） | #24、#26 |
| M1-6 | #84 の承認と UI 実装の開始条件 | **M1 で使う画面だけを先に部分承認してもらう。** 対象は Map（S02）と地点詳細（S03）、その読込・空・失敗・保存版・未掲載の状態で、node ID・承認者・承認日を記録する。経路・案内の画面は #84 全体の承認を待つ | #84、#85、#31 |
| M1-7 | 新しい版を受信したときの表示の切替（E2-5 §6 規則5） | **暫定：保存はすぐ行い、表示中の地図・詳細は古い版のまま保つ。詳細を閉じたとき、または Map タブを開き直したときに切り替える。** 手動の再読み込みは M1 では作らない。正式な扱いは #84・#85 で決める | #85、#84、#109 |

## 3. 既存の記載との食い違い

- **#24**：本文は「描画方式を比較・採用する」「特定 SDK は検証・決定前に確定しない」としている。M1-5 は比較を省き MapKit を前提にした。MapKit は OS 標準のフレームワークであり外部 SDK の追加はないが、#24 の完了条件は「比較」から「MapKit の採用記録と通信断時の表示の検証」に読み替える。通信断で構内図が表示できないと分かった場合は、本判断を見直す。

## 5. M1 の受入条件

1. Studio の公開操作から、隔離環境（PG17・Caddy）の public-api を経て、iOS シミュレーターに 14棟の建物 Spot が表示される。
2. 公開した部屋・ランドマークが、bundle と同じ canonical ID・位置で表示される。
3. 地点を選ぶと、同じ canonical ID の地点詳細が表示される。未知・未公開の ID は別の地点に置き換えず「未掲載」と表示する。
4. 304、通信断、破損した bundle、版の後退、更新の失敗のいずれでも、保存済みの版が壊れずに表示され続ける。
5. fixture での表示を、Studio から正式データが届いたことの証跡にしない。隔離環境での成功を本番適用済みとは扱わない。
6. M1 の完了をもって #85 は Close せず、`main` へもマージしない。
