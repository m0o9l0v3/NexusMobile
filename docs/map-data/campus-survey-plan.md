## 0. 守ること

- **Apple・Google の地図は、どの手順でも資料にしない。** 形・座標・基準点・距離の見当・初期値のどれにも使わない。地図アプリを開いて見比べることもしない。
- 国土地理院の基盤地図情報は、**現状と合っていると確かめた建物にだけ**使う（§3）。
- 航空写真（地理院タイル）は**確認だけ**に使い、形をなぞらない（改訂4 §3 の K-3）。
- スマートフォンの GPS は根拠にしない（誤差 5〜10 m）。本書では、どの古い建物が近いかの見当をつけるためだけに使う（§4.1）。
- 建物ごとに、資料・取得日・方法・利用条件・精度を記録する（§7）。
- 野帳には人の名前を書かない。オーナーが決めた役割名か頭文字を書く（§5.3）。

## 2. 国土地理院の基盤地図情報を手に入れる

### 2.1 ダウンロードと変換

| 段階 | すること | 注意 |
|---|---|---|
| 1 | 国土地理院の「基盤地図情報ダウンロードサービス」（`https://service.gsi.go.jp/kiban/`）で利用者登録をする（無料） | ダウンロードには ID とパスワードが要る |
| 2 | 「基本項目」を選び、キャンパスを含む **2次メッシュ** を選んでダウンロードする | 形式は JPGIS（GML）。項目「建築物の外周線」（BldL）を使う |
| 3 | 取得日・メッシュ番号・ファイル名・データの更新日を記録する（§7） | 元の zip は `map-data/raw/<取得日>/gsi-fgd/` には置かず、リポジトリの外に保管し、SHA-256 だけを記録する（既存の写真原本と同じ扱い。`map-data/README.md`） |
| 4 | 同じサイトの「基盤地図情報ビューア」（FGDV）で GML を開き、建築物の外周線を **Shape 形式**で書き出す | 書き出すときの座標は**緯度経度**（投影しない）を選ぶ |
| 5 | QGIS で Shape を開き、キャンパスの範囲だけ切り出して、**EPSG:4326 の GeoJSON** で保存する | 保存のときに「座標の精度」を 7 桁以上にする（最後に Nexus のツールが 6 桁へ丸める） |

- **座標系**: 2025-07-31 以降に提供されるデータの座標参照系は JGD2024（それより前は JGD2011）。ダウンロードしたデータに書かれた座標系を記録する。本書では JGD2024・JGD2011 の緯度経度を WGS 84 と同じ値として扱う（日本の慣行）。両者の差（プレートの動きによる、北海道でおおむね 1 m 未満と見込む。**要確認**）はキャンパス全体に共通の平行移動であり、建物どうしの位置関係は変えない。
- **精度**: 基本項目の精度は、都市計画区域では「縮尺 1/2,500 相当」、区域外では「縮尺 1/25,000 相当」（ダウンロードサービスのヘルプ）。キャンパスがどちらに当たるかを、ダウンロードしたデータの属性（縮尺レベル）で確かめて記録する。**1/25,000 相当なら、基準点には使えない**（誤差が 1 m の目標より大きい）。その場合はハブのセッションに知らせる（計画の見直しが要る）。
- 外周線は、地上の壁の位置と屋根の張り出しのどちらを描いているかが建物によって違いうる。§3 の照合で、壁の角を測って確かめる。

### 2.2 測量成果の利用手続（オーナーが確かめる）

基盤地図情報は測量法の基本測量成果で、使い方によって複製（第29条）または使用（第30条）の承認が要る。**本書では申請しない。** 確かめる手順:

1. 国土地理院「国土地理院の測量成果の利用手続」（`https://www.gsi.go.jp/LAW/2930-index.html`）と「承認申請Q&A」（`https://www.gsi.go.jp/LAW/2930-qa.html`）を読む。関わりの深い問は Q1-16・Q1-17・Q1-18・Q2-6・Q5-4。
2. 「地図の利用手続ナビ」（`https://service.gsi.go.jp/onestop/navi/index/`）で、Nexus の使い方を選んで答えを確かめる。Nexus の使い方は次のとおり書く:
   - 基盤地図情報の建築物の外周線から、現状と合う建物の頂点の座標を取り出し、独自の GeoJSON（アプリの地図データ）にする。
   - 合う建物の角を基準点にして、新しい建物を現地で測る。
   - アプリでは Apple の地図の上に、独自の建物の形を重ねて表示する。配布は App Store の iOS アプリ。
3. 判断がつかなければ、国土地理院の「基盤地図情報の複製・使用承認について」の問い合わせ窓口に、上の3点を書いて尋ねる。
4. 申請が要るとなれば、「測量成果ワンストップサービス」（`https://service.gsi.go.jp/onestop/`）から申請する（手数料なし、標準の処理期間は 7〜14 日程度）。承認番号と出典の書き方を §7 の `terms` に記録する。
5. どの場合でも、出典（「基盤地図情報（国土地理院）」など、承認や Q&A が示す書き方）を、アプリの表示と公開サイトのどこに書くかを決める。

利用手続の答えが出るまで、国土地理院の座標を**公開する GeoJSON に入れない**。現地測量（§4）と、手元での計算（§6）は先に進めてよい（データを公開しないため）。

## 3. 古い7棟を国土地理院のデータと照らし合わせる

### 3.1 照らし合わせる理由

古い7棟の角は、新しい棟を測る**基準点**になる。基準点が間違っていれば、そこから測った新しい棟もすべてずれる。そこで、基準点に使う前に、国土地理院の形が現状と合っているかを現地で確かめる。

### 3.2 現地で測るもの

国土地理院の GeoJSON を印刷し、各棟の角に `<ID>-G1`, `-G2`, … と番号を振る（北東の角から時計回りなど、どの棟も同じ決め方で）。

| 測るもの | 内容 |
|---|---|
| 各辺の長さ | すべての辺を、壁の角から角まで測る。凹凸の小さい辺（1 m 未満）は、国土地理院の形に無ければ記録だけする |
| 対角線 | 4つ角の建物は1本以上。形の歪み（平行四辺形になっていないか）を見る |
| 建物どうしの距離 | 基準点に使う角どうしを、**別の建物の間で**最低1本ずつ（例: `ar` の角 ↔ `ab` の角）。建物の位置関係が国土地理院のとおりかを見る |

野帳には、建物の角どうしの観測として書く（`from_point` と `point_id` の両方が `<ID>-G*`）。§6 のツールは、両端が基準点の観測を「基準点の照合」として、国土地理院の座標から出した距離と比べる（調整には入れない）。

### 3.3 合っているとみなす基準

| 項目 | 基準 |
|---|---|
| 各辺の長さ | 測った長さと国土地理院の長さの差が **±0.5 m 以内**（短い辺の凹凸は除く） |
| 対角線 | 差が ±0.5 m 以内 |
| 建物どうしの距離 | 差が **±1.0 m 以内**（ツールの既定値 `reference_check_m`） |
| 形 | 角の数・大きな凹凸が現状と同じ（増築・取り壊しが無い） |

辺が ±0.5 m を超えた棟は「合っていない」とし、その棟の角を基準点にしない。±0.5 m は、1/2,500 相当の図と巻尺・レーザーの測り方の差として見込める幅で、1 m の目標の半分に収めるために置いた。照らし合わせの結果を見て、ハブのセッションと見直してよい（見直したら本書を直す）。

### 3.4 合わなかった棟

- その棟を基準点に使わない。
- その棟は、新しい棟と同じ方法（§4）で現地で測って作り直す。§7 の `geometry_source` は `field_survey` にする。

### 3.5 基準点の候補

基準点にする角は、次を満たすものを選ぶ。

- 壁の角がはっきりしていて、地面の高さで当てられる（植え込み・ひさしの下でない）。
- 新しい棟の角から**見通せる**（レーザーが届く）か、巻尺を張れる。
- 1つの新しい棟について、**2つ以上の別の建物**の角を使う（同じ建物の角だけだと、その建物が丸ごとずれていても気づけない）。

§4.1 の表で、新しい棟ごとの候補の建物を挙げた。どの角を使うかは、下見（§5.2 の1）で決め、野帳の「基準点の一覧」に書く。

## 4. 新しい7棟を測る

### 4.1 棟ごとの基準点の候補

候補の建物は、2026-07-19 と 2026-09-19 に撮った入口の写真の GPS（`map-data/normalized/entrances.csv`、誤差 3〜5 m）どうしの距離で見当をつけた。入口から入口までの距離なので、建物の角どうしはこれより近いことが多い。距離は下見の目安で、測量の根拠にはしない。Apple・Google の地図も、出どころを確かめていない QGIS の原本の形も使っていない。`aptr`・`ptb` には入口の記録が無い（屋外直結の入口を登録しない棟）ため、距離を出していない。

| 新しい棟 | 近い古い棟（入口どうしのおおよその距離） | 基準点の候補 | 仮の点 |
|---|---|---|---|
| `amh` 女子寮 | `dh` 約10 m、`lbh` 約35 m、`ar` 約70 m | `dh` の角2つ ＋ `lbh` の角1つ以上 | 不要の見込み |
| `ctc2` CTC2 | `ar` 約20 m、`ab` 約75 m | `ar` の角2つ ＋ `ab` の角1つ | `ab` が遠ければ1点 |
| `ctc_main` CTC | `ab` 約50 m、`ar` 約50 m、`mb` 約70 m | `ar` の角 ＋ `ab` の角 | 見通しによる |
| `dvh` Da Vinci Hall | `dh` 約100 m、`ar` 約100 m | `ar` の角2つ ＋ `dh` の角 | **要**（1〜2点） |
| `hgr_a` 格納庫A | `mb` 約85 m、`ab` 約100 m | `mb` の角 ＋ `ab` か `ptb` の角 | **要**（2点） |
| `hgr_b` 格納庫B | `hgr_a` と同じ入口位置（同じ進入路） | `hgr_a` と同じ。測り終えた `hgr_a` の角も使える | `hgr_a` と共用 |
| `sab` 技能審査棟 | `aptr`・`ptb`（距離は下見で確かめる） | `aptr` の角2つ ＋ `ptb` の角1つ | 見通しによる |

- `ar`（アリーナ）は4棟の基準になる。**§3 の照合を最初に `ar` で行う。** `ar` が合わなければ、`ab`・`dh` を主にして計画を組み直す。
- `hgr_a`・`hgr_b`・`dvh` は基準点から 50 m を超える見込み。50 m を超える距離はレーザー距離計で測る。届かなければ、間に**仮の点**（杭・チョークの印。ID は `T1`, `T2`, …）を置き、仮の点を基準点から測り（§4.2 と同じく2点以上から）、そこから建物の角を測る。

### 4.2 測るもの（1棟ごと）

角に `<ID>-P1`, `-P2`, … と番号を振る（外周を回る順。どちら回りでもよい。ツールが反時計回りに直す）。

| # | 測るもの | 数 | 目的 |
|---|---|---|---|
| 1 | 各角から、基準点（または仮の点）までの距離 | 角ごとに **2点以上**、できれば3点。2点はなるべく直角に近い方向から | 角の位置を決める（2つの円の交点） |
| 2 | すべての辺の長さ | 全辺 | 形を決める。1の照合になる |
| 3 | 対角線 | 4つ角なら1本以上、それより多い角なら離れた角どうしを2本以上 | 直角か（歪んでいないか）を見る |
| 4 | 最初の角の、基準点からのおおよその方位（コンパス） | 1棟に1つ | 2つの円の交点のどちらかを決めるため。計算の精度には使わない |
| 5 | 仮の点どうしの距離・仮の点から基準点への距離 | 仮の点ごとに3件以上 | 仮の点の位置を決める |

- **水平距離**を書く。段差・斜面があるときは、レーザー距離計の水平距離の表示を使うか、巻尺を水平に張る。
- 角は**地面の高さの壁の角**に当てる。ひさし・雨どい・基礎の出っ張りは避け、何に当てたかを `notes` に書く。
- 入口（#16）も同じ日に測ると、あとで外へ出る回数が減る。正式入口の位置は、建物の角からその辺に沿った距離（巻尺）を `notes` に書いておく（`mb_ent_001` は Google マップ由来なので、測り直す対象。改訂4 §5.3）。

### 4.3 冗長性と、測り直しの基準

**なぜ冗長にするか。** 角の位置は、2つの距離があれば決まる。ところが2つだけだと、どちらかを読み違えても（例: 23.4 m を 24.3 m と書く）計算はそのまま通り、間違った位置が出る。3つ目の距離や辺の長さがあれば、すべてが同時には合わなくなるので、間違いに気づける（**閉合の照合**）。§6 のツールは、全部の観測を最小二乗でまとめて解き、各観測が計算の位置とどれだけ合わないか（残差）を出す。

ツールは次のどれかに当たると「測り直し」とし、GeoJSON を書き出さない（既定値。測量設定の `tolerances` で変えられるが、変えたら理由を §7 の `notes` に書く）。

| 基準 | 既定値 | 当たったときにすること |
|---|---|---|
| 1つの観測の残差 | **±0.30 m** を超える | その観測を測り直す。直らなければ、同じ角に関わる観測を順に測り直す |
| 角の位置の標準偏差（1σ、水平） | **0.40 m** を超える（95% でおおむね 1 m） | 別の方向の基準点からも測る（基準点の配置が悪い） |
| 角ごとの冗長性 | ほかの点（基準点・仮の点・別の建物の角）が2点未満、または観測が3件未満 | 足りない観測を足す |
| 仮の点の冗長性 | 観測が3件未満 | 足りない観測を足す |
| 基準点どうしの照合 | 国土地理院の座標との差が **±1.0 m** を超える | §3 のとおり、その基準点を使わない |

- **当日のうちに**、現場で判断できるようにする。辺の長さの読み違いは、その場で「辺の和」「対角線と辺（三平方）」で暗算して気づけることが多い（4つ角の建物なら、対角線² ≈ 辺1² ＋ 辺2²）。
- 測り直した行は消さずに、`void` 列に理由と新しい記録番号を書く（例: `再測定 → A031`）。ツールは `void` の行を計算に入れない。
- 2点だけを基準にした建物（仮の点2点からだけ測った格納庫など）は、建物全体が鏡に映したように反対側に出ても計算が合ってしまう。方位（§4.2 の4）を必ず記入し、ツールが出した形を現地のスケッチ・写真と見比べる。

### 4.4 作業の順序

1. 古い棟の照合（§3）。`ar` → `dh`・`lbh` → `ab`・`mb` → `aptr`・`ptb` の順に、基準点に使う角を確かめる。
2. 基準点に近い棟から: `ctc2` → `ctc_main` → `amh` → `sab`
3. 仮の点が要る棟: `dvh` → `hgr_a` → `hgr_b`
4. 1棟終わるごとに、辺と対角線の暗算での照合をする。
5. その日の終わりに野帳を CSV に入れ、§6 のツールを回す。測り直しがあれば、翌日の最初に測る。

### 5.2 人と段取り（2人）

| 役割 | すること |
|---|---|
| 測る人（例: `A`） | 距離計・巻尺の基点側。読み上げる |
| 記録・ターゲット（例: `B`） | 角にターゲット板・巻尺の先を当てる。野帳に書き、読み返す（**読み上げと読み返しを必ずする**） |

1. **下見（1時間）**: 各新しい棟を回り、角を数えて番号を振り、使う基準点の角を決め、見通しを確かめる。野帳の「基準点の一覧」を埋める。
2. **古い棟の照合（2〜3時間）**: §3。
3. **新しい棟（1棟 30〜60分）**: §4.4 の順。7棟でおおよそ1日。
4. **その日のうちに入力・計算（1時間）**: §6。測り直しを書き出す。
5. **予備日（半日）**: 測り直し。

2日に分けてよい（1日目: 下見・照合・基準点に近い棟。2日目: 仮の点が要る棟・測り直し）。

### 5.3 安全と許可

- 学校の許可を持ち歩き、聞かれたら見せる。測る日時を事前に学校の担当に伝える。
- **授業時間・休み時間の移動の多い時間を避ける。** オープンキャンパス・行事の日は避ける。
- 通路・車路を巻尺でふさがない。車路をまたぐときは1人が見張る。
- 格納庫の周り（`hgr_a`・`hgr_b`）・機体実習の場所は、立ち入ってよい範囲を担当に確かめる。機体・車両の動く時間を避ける。
- **レーザーを人の目・車の運転席に向けない。** 窓ガラスに当てない（反射）。
- 屋根・はしごには上らない。地面から測れない角は、測れる2点と辺の長さから計算する（`notes` に書く）。
- 生徒・職員の顔・名前が写る写真を撮らない。野帳には人の名前を書かない（役割名か頭文字）。

## 6. 測った値から GeoJSON を作る

### 6.1 選んだ方法

小さなスクリプトを実装した（本 PR）: [`tools/map-dataset/survey.mjs`](../../tools/map-dataset/survey.mjs)（実体は `src/survey/`、テストは `test/survey.test.mjs`）。新しいライブラリは入れていない（既存の `transform.mjs` の WGS 84 ↔ 局所ENU を使う）。

1. 基準点（国土地理院の座標）を、キャンパスの原点のまわりの**局所ENU**（メートル）に変える（E1-5 と同じ計算。原点は測量設定の `origin`、無ければ基準点の平均）。
2. 各角の初期値を、2つの円の交点で決める。2候補のどちらかは、3つ目の距離か、方位（コンパス、偏角を足して真北に直す）で選ぶ。方位は初期値にだけ使い、計算の精度には入れない。
3. 全部の距離の観測を、**重み付き最小二乗**（Gauss-Newton）でまとめて解く。基準点は固定。重みは機材ごとの `sigma_m + sigma_per_m × 距離` から。
4. 残差・各角の標準偏差・自由度・単位重みの標準偏差（σ0）を出し、§4.3 の基準で「測り直し」を判定する。
5. 角を WGS 84 に戻し、**小数6桁**に丸め、反時計回りの閉じた環の Polygon にする。

### 6.2 使い方

```bash
npm run mapdata:survey -- \
  --project <測量設定.json> \
  --observations <野帳.csv> \
  --report <レポート.json> \
  --out <建物.geojson> \
  --provenance-out <出典の行.csv>
```

- 測量設定のひな形: [`map-data/survey/templates/survey-project.template.json`](../../map-data/survey/templates/survey-project.template.json)。基準点（§3 で確かめた角の、国土地理院の緯度経度）・機材の精度・建物の角の順・仮の点を書く。基準点の `source` に Apple・Google の地図を書くと、ツールは拒否する。機材の精度のひな形（`sigma_m` 0.05 m ＋ 1 m あたり 1 mm）は、機材そのものの精度（数 mm）に、壁の角に当てる誤差と巻尺のたるみを足した見込みである。
- 野帳の CSV: [`map-data/survey/templates/field-sheet.csv`](../../map-data/survey/templates/field-sheet.csv)（列は §6.3）。スマートフォン用のスプレッドシートで記入したときは、その「CSV」シートをカンマ区切り形式でダウンロードすればこの形になる。
- 終了コード 0 = すべて許容値内、1 = 測り直しがある（GeoJSON は書き出さない。`--allow-remeasure` で下見・練習用に書き出せる）、2 = 入力の誤り。
- レポートには、建物ごとの角の位置・標準偏差・残差、基準点の照合、測り直しの一覧が入る。

### 6.3 野帳の列

| 列 | 内容 |
|---|---|
| `record_id` | 記録番号（日付と連番など。重複不可） |
| `building_id` | 測っている建物（照合なら古い棟の ID） |
| `point_id` | 測った点（建物の角 `<ID>-P*`、古い棟の角 `<ID>-G*`、仮の点 `T*`） |
| `from_point` | どこから測ったか（基準点・仮の点・同じ建物の別の角） |
| `distance_m` | 水平距離 [m]。小数3桁まで |
| `bearing_deg` | `from_point` から `point_id` への方位（磁北、度）。初期値用。空欄でよい |
| `instrument_id` | 機材（測量設定の `instruments` のキー。例: `LD1` レーザー、`TP1` 巻尺） |
| `measurer` | 役割名か頭文字（名前は書かない） |
| `observed_at` | 日時（`2026-12-01T10:15`） |
| `photo_ref` | 写真のファイル名 |
| `notes` | 何に当てたか、障害物など |
| `void` | 無効にした理由（測り直した行）。有効な行は空欄 |

### 6.4 原本と対応設定へのつなぎ方

- ツールが出す GeoJSON は、map-dataset の `geojson` 原本と同じ形（`properties.id` に建物 ID）で、出典（`geometry_source`・`survey_dates`・`reference_point_ids`・`accuracy_m_1sigma`・`max_abs_residual_m` など）を `properties` に持つ。map-dataset は配布の GeoJSON にこれらを持ち込まない（E1-4 の `building` は `feature_type`・`name`・`access_node_id` だけ）。出典は §7 の表に残す。
- 古い棟で国土地理院と合ったものは、§2 の GeoJSON から、その棟の外周線を1つずつ選んで、同じく `properties.id` に建物 ID を付けた GeoJSON にする（形はそのまま。頂点を動かさない）。
- 2つの GeoJSON をリポジトリの外の原本フォルダ（今の `確定版geojson/` と同じ場所）に置く。原本 `nexus_campus_canonical_20260724.geojson` は**変更しない**。
- [`campus-buildings.config.json`](../../tools/map-dataset/config/campus-buildings.config.json) に `geojson` の原本を2つ足し（例: `survey_buildings`・`gsi_buildings`）、14棟の `features` の `source` をそちらに切り替える。旧原本の14棟は `exclude`（理由コード例 `superseded_by_survey`）にする。これは測量が済んでからの別の PR で行う（本 PR では設定を変えない）。
- 切り替えたら、`publish_readiness` の `building_geometry_unmeasured` を外せるかを確かめる。
