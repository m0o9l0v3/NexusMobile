## 0. 守ること

- **Apple・Google の地図は、どの手順でも資料にしない。** 形・座標・基準点・距離の見当・初期値のどれにも使わない。地図アプリを開いて見比べることもしない。
- 国土地理院の基盤地図情報は、**現状と合っていると確かめた建物にだけ**使う（§3）。古い7棟は、照合のうえ**基盤地図情報の形から作り直す**（QGIS 原本の形に国土地理院の名前を付け替えるのではない）。
- 航空写真（地理院タイル）は**確認だけ**に使い、形をなぞらない（改訂4 §3 の K-3）。
- スマートフォンの GPS は根拠にしない（誤差 5〜19 m）。本書では、どの建物が近いかの見当をつけるためだけに使う（§4.9）。入口の位置（`map-data/normalized/entrances.csv`、写真の GPS。`mb_ent_001` は Google マップ由来）は、**すべて測量した位置に置き換える**（§4.3）。
- ウォーキングメジャーは**舗装面の経路の長さにだけ**使う。建物の角・分岐・入口は、巻尺かレーザー距離計で測る（§4.1）。
- 点・建物ごとに、資料・取得日・方法・利用条件・精度を記録する（§10）。
- 野帳には人の名前を書かない。オーナーが決めた役割名か頭文字を書く（§7.3）。

## 2. 国土地理院の基盤地図情報を手に入れる

### 2.1 ダウンロードと変換

オーナーが 2026-11-16 にダウンロード済み: 2次メッシュ **644114**、基本項目、データの日付 2026-07-01（`FG-GML-644114-ALL-20260701`）。14棟はすべてこのメッシュに入る。2026-11-18 に隣の **644115** も取得した（zip は `Nexus/gsi-data/`、リポジトリの外）。

| 段階 | すること | 注意 |
|---|---|---|
| 1 | 「基盤地図情報ダウンロードサービス」（`https://service.gsi.go.jp/kiban/`）で利用者登録をし、「基本項目」の 2次メッシュ 644114 をダウンロードする | 済 |
| 2 | 取得日・メッシュ番号・ファイル名・データの日付を記録する（§10） | zip はリポジトリに置かず、手元に保管し SHA-256 だけを記録する（`map-data/README.md` の写真原本と同じ扱い） |
| 3 | **Mac で変換する**: `npm run mapdata:fgd -- --input <…-BldA-…xml> --bbox <範囲> --out <campus-gsi.geojson>` | Windows 専用の基盤地図情報ビューアは使わない。GML は「緯度 経度」の順なので、QGIS で GML をそのまま開くと軸が入れ替わって別の場所に出ることがある。このツールが [経度, 緯度] に並べ替える |
| 4 | 出た GeoJSON を QGIS で開き、古い7棟に当たる建物の `gml_id` を確かめる（§3.2） | 座標は丸めていない（map-dataset が6桁に丸める） |

- **使う項目**: `BldA`（建築物, 面）。外周が閉じた Polygon なので、そのまま建物の形にできる。`BldL`（建築物の外周線）は線で、面にするには繋ぎ直しが要るので、`BldA` が無い場合だけ使う。
- **座標系**: ダウンロードしたデータは **JGD2024** の緯度経度（`fguuid:jgd2024.bl`）。本書では JGD2024・JGD2011 の緯度経度を WGS 84 と同じ値として扱う（日本の慣行）。両者の差はキャンパス全体に共通の平行移動で、建物どうしの位置関係は変えない。差の大きさは**要確認**（§9 の照合点で確かめられる）。
- **精度**: 644114 の `BldA` は 8,751 件中 8,737 件が `orgGILvl=2500`（地図情報レベル2500。位置の標準偏差 1.75 m 以内とされる）。残り 14 件は 25000。照合（§3）に使う建物が 2500 であることを `orgGILvl` で確かめる。
- 外周線は、地上の壁の位置と屋根の張り出しのどちらを描いているかが建物によって違いうる。§3 の照合で、壁の角を測って確かめる。
- キャンパスの範囲の建物（`BldA`・`BldL`）と道路縁（`RdEdg`）・道路構成線（`RdCompt`）は、すべて `orgGILvl=2500`（2026-11-18 確認）。土台として使える。
- **キャンパスの近くに基準点（`GCP`・`SBAPt`）は無い**。絶対精度を確かめる照合点は、基準点成果等閲覧サービスで別に探す（§9）。
- 構内の道路は、一部だけが `庭園路等` の道路縁として載っている。経路の辺がすべて国土地理院にあるとは考えない（§5）。

## 3. 古い7棟を国土地理院のデータと照らし合わせる

### 3.1 照らし合わせる理由

古い7棟の角は、新しい棟と経路を測る**基準点**になる。基準点が間違っていれば、そこから測ったものもすべてずれる。そこで、基準点に使う前に、国土地理院の形が現状と合っているかを現地で確かめる。

### 3.2 どの国土地理院の建物か

§2.1 の GeoJSON で、古い7棟に当たる建物を確かめる。今の原本（`nexus_campus_canonical_20260724.geojson`）の多角形と国土地理院の `BldA`（2026-07-01 版、穴を含めた面）を重ねると、次のとおり（2026-11-18。重なり＝原本の面積のうち国土地理院の建物に入る割合。**候補**。QGIS で形と位置を見て、オーナーが決める）。

### 3.3 現地で測るもの

各棟の角に、国土地理院の外周の頂点の順で `<ID>-G1`, `-G2`, … と番号を振る（`fgd-to-geojson` が出す環の順。野帳の作り直し（§11）で一覧に入る）。

| 測るもの | 内容 |
|---|---|
| 各辺の長さ | すべての辺を、壁の角から角まで巻尺かレーザーで測る。凹凸の小さい辺（1 m 未満）は、国土地理院の形に無ければ記録だけする |
| 対角線 | 4つ角の建物は1本以上。形の歪み（平行四辺形になっていないか）を見る |
| 建物どうしの距離 | 基準点に使う角どうしを、**別の建物の間で**最低1本ずつ（例: `ar` の角 ↔ `ab` の角）。建物の位置関係が国土地理院のとおりかを見る |

野帳には、角どうしの距離として書く（`from_point` と `point_id` の両方が `<ID>-G*`）。ツールは、両端が基準点の観測を「基準点の照合」として、国土地理院の座標から出した距離と比べる（調整には入れない）。

### 3.4 合っているとみなす基準

| 項目 | 基準 | ツールの設定 |
|---|---|---|
| 同じ建物の各辺・対角線 | 測った長さと国土地理院の長さの差が **±0.5 m 以内**（短い辺の凹凸は除く） | `reference_side_check_m`（既定 0.5） |
| 建物どうしの距離 | 差が **±1.0 m 以内** | `reference_check_m`（既定 1.0） |
| 形 | 角の数・大きな凹凸が現状と同じ（増築・取り壊しが無い） | 目で確かめる |

辺が ±0.5 m を超えた棟は「合っていない」とし、その棟の角を基準点にしない。±0.5 m は、地図情報レベル2500 の図と巻尺・レーザーの測り方の差として見込める幅で、1 m の目標の半分に収めるために置いた。ツールは同じ `building_id` の基準点どうしに 0.5 m、別の建物どうしに 1.0 m を当てる。

合わなかった棟は、基準点に使わず、新しい棟と同じ方法（§4）で測って作り直す（§10 の `geometry_source` は `field_survey`）。

### 3.5 基準点の選び方

- 壁の角がはっきりしていて、地面の高さで当てられる（植え込み・ひさしの下でない）。
- 新しい棟の角・経路の点から**見通せる**（レーザーが届く）か、巻尺を張れる。
- 1つの新しい棟・1本の基線について、**2つ以上の別の建物**の角を使う（同じ建物の角だけだと、その建物が丸ごとずれていても気づけない）。

## 4. 測り方

### 4.1 機材の使い分け

| 測るもの | 機材 | 精度の見込み（1σ） |
|---|---|---|
| 舗装面の経路の長さ（基線に沿った累積距離） | **ウォーキングメジャー** | 0.1 m ＋ 長さの約 1%（`sigma_m` 0.1、`sigma_per_m` 0.01） |
| 建物の角・分岐・入口の位置、建物の辺・対角線、支距 | **巻尺 50 m** か **レーザー距離計** | 0.05 m ＋ 1 m あたり 1 mm |
| 直角（支距を下ろす向き） | **直角プリズム**か、巻尺で **3-4-5** を確かめる | 0.5°（プリズム）・1°（3-4-5） |

- ウォーキングメジャーは、芝・砂利・段差では車輪が滑ったり跳ねたりする。舗装面以外では使わない。
- ウォーキングメジャーの**目盛りの誤差**（例: 1 m 進むと 1.02 m と出る）は、行きと帰りで同じ向きにかかる。往復しても打ち消し合わないので、往復は読み違いを見つけるためにしか役に立たない。目盛りは §6 の試行で校正し、`scale_factor` に入れる。

### 4.2 基線と支距（累積距離＋垂直距離）

道路に沿って、両端が分かっている点（ノード、国土地理院で確かめた古い棟の角、すでに測った点）を結ぶ**基線**を決める。基線の起点から、点を基線に下ろした足までの距離（**累積距離** `s`）と、基線から点までの垂直距離（**支距** `d`）を測る。

- 累積距離はウォーキングメジャー、支距は巻尺かレーザー。
- 支距は、基線に**直角**に下ろす。直角プリズムで向きを決めるか、巻尺で 3-4-5（3 m・4 m・5 m の三角形）を作って確かめる。直角の向きが 2° ずれると、支距 20 m で足の位置が約 0.7 m ずれる。**支距は 15 m までを目安**にし、それより長いときは別の点からの距離を1本足す（ツールは 15 m を超えると注意を出す）。
- 左右は、基線の起点から終点へ歩いたときの向きで書く（`R` 右・`L` 左）。
- 支距だけで決めた点は、照合ができない。**3本目の距離**（近くの角や別の点からの巻尺・レーザー）を必ず1本足す。
- 野帳では `obs_type` を `chainage_offset`（支距）にし、`baseline_id`・`chainage_m`・`offset_m`・`offset_side`・`offset_instrument_id` を書く（§8.3）。測量設定の `baselines` に、基線の ID と起点・終点を書く。

支距をツールに入れないで計算する場合は、累積距離 `s` と支距 `d` から、基線の起点 A・終点 B の位置で P = A + s·u + d·n（u は A→B の単位ベクトル、n はその右向きの直交ベクトル）とすればよい。ツールは同じ式を観測として最小二乗に入れている。

### 4.3 建物の角・分岐・入口

- 角・分岐・入口は、近くの点から**短い基線**（巻尺 1 本で届く長さ）を使い、巻尺かレーザーで測る。2本で位置を決め、**3本目で確かめる**。
- 入口は `{building_id}_ent_{seq:03}`（E1-2）の ID で、ドアの中央の敷居の位置を測る。`entrances.csv` の写真の GPS の位置は使わない（すべて置き換える）。
- `ptb`・`aptr` は、来場者が屋外から直接入る入口があるか（`mb` から屋内で連絡するだけか）を現地で確かめる（§5.3）。

### 4.4 建物の形

外周を1周して辺を足していくと、誤差が積み重なり、最後に閉じなくなる。そこで、**全体の幅 W × 奥行き D と対角線**を主に測る。

- 長方形の棟: W・D・対角線2本。対角線² ≈ W² ＋ D² で直角を確かめる。
- コの字の棟: 全体の W・D に加え、凹みの幅 `w`・奥行き `d`・端から凹みまでの距離 `a` を測る。角は (0,0)・(W,0)・(W,D)・(a+w,D)・(a+w,D−d)・(a,D−d)・(a,D)・(0,D) になる。外周の長さの合計は 2W ＋ 2D ＋ 2d になるので、測った辺の合計と比べて確かめる。
- 壁際に植え込みや物があって角に当てられないときは、**平行オフセット法**: 壁から 2〜3 m 離れた舗装面に、壁と平行に巻尺を張り（両端で壁までの垂直距離が同じことを確かめる）、その線に沿って長さを測る。角の位置は、オフセット線から壁までの垂直距離を引いて求める。
- 角の位置そのもの（基準点・基線からの距離・支距）は §4.2・§4.3 の方法で、手前の2つの角を最低限測る（オーナーの方針: 手前2角の `s1`・`d1`・`s2`・`d2` で位置と傾きを決める）。ほかの角は W・D・対角線と、3本目の距離で決める。

### 4.5 斜面・段差

距離は**水平距離**で使う。傾いたところで測った**斜距離**は、野帳に傾斜角 `slope_deg`（度）か高低差 `height_diff_m`（m）を書けば、ツールが水平距離に直す（水平 = 斜距離 × cos 傾斜角、または √(斜距離² − 高低差²)）。レーザー距離計に水平距離の表示があれば、それを書いて傾斜の欄は空にする。

### 4.6 曲がり角（分岐の無いもの）

分岐の無い曲がり角は、経路のノードにしない。`walking_path` の **LineString の途中の頂点**（折れ点、測量設定の `points` で `kind: "bend"`）として、基線からの累積距離と支距で測る。線の形が要る場所だけ測ればよい（オーナーの方針）。折れ点は観測2件（累積距離・支距）でよいが、照合はできないので、気になる所は近くの壁までの距離を1本足す。

### 4.7 輪（閉合）の照合

`campus_n_002`（N02）から `campus_n_010`（N10）を回る経路は、輪になっている。

- ツールは、測量設定の `loops` に書いた輪について、**測った区間の長さの合計と、調整後の形の長さの合計の差**（閉合差）を出し、区間ごとの残差を並べる。
- 最小二乗は、閉合差を各区間に**配るだけ**で、どこで測り違えたかは直さない。閉合差が大きいときは、その輪の区間を測り直す。
- **累積距離だけでは、点の座標は決まらない**（長さだけのパズルでは、四角形の輪は角度が自由に動く）。輪のノードには、国土地理院で確かめた古い棟の角からの距離（**結合**）を、ノードごとに最低1本測る。

### 4.8 冗長性と、測り直しの基準

**なぜ冗長にするか。** 点の位置は、2つの観測があれば決まる。ところが2つだけだと、どちらかを読み違えても（例: 23.4 m を 24.3 m と書く）計算はそのまま通り、間違った位置が出る。3つ目の観測があれば、すべてが同時には合わなくなるので、間違いに気づける（**閉合の照合**）。ツールは、全部の観測を最小二乗でまとめて解き、各観測が計算の位置とどれだけ合わないか（残差）を出す。

ツールは次のどれかに当たると「測り直し」とし、GeoJSON を書き出さない（既定値。測量設定の `tolerances` で変えられるが、変えたら理由を §10 の `notes` に書く）。

| 基準 | 既定値 | 当たったときにすること |
|---|---|---|
| 1つの観測の残差 | **±0.30 m** を超える | **その日のうちに**、その観測を測り直す。直らなければ、同じ点に関わる観測を順に測り直す |
| 点の位置の標準偏差（1σ、水平） | **0.40 m** を超える（95% でおおむね 1 m） | 別の方向の点からも測る（配置が悪い） |
| 点ごとの冗長性 | ほかの点（基準点・仮の点・基線の端・別の建物の角）が2点未満、または観測が3件未満（折れ点は2件） | 足りない観測を足す |
| 基準点どうしの照合 | 同じ建物 **±0.5 m**、建物どうし **±1.0 m** を超える | §3.4 のとおり、その基準点を使わない |
| 輪の閉合差 | 0.30 m × √（区間の数）を超える | 輪の区間を測り直す |
| 支距の長さ | 15 m を超える（注意だけ） | 3本目の距離を足す |

- 現場で判断できるようにする。辺の読み違いは、その場で「対角線² ≈ 辺1² ＋ 辺2²」の暗算で気づけることが多い（野帳の「棟ごと」シートが自動で出す）。
- 測り直した行は消さずに、`void` 列に理由と新しい記録番号を書く（例: `残差 0.45 m → R031`）。ツールは `void` の行を計算に入れない。
- 2点だけを基準にした点（仮の点2点からだけ測った格納庫など）は、鏡に映したように反対側に出ても計算が合ってしまう。方位（コンパス）を1つ記入し、ツールが出した形を現地のスケッチ・写真と見比べる。

## 5. 経路（ルート1〜4）

経路のノード 13 点と辺 14 本の下書き（[`map-data/drafts/`](../../map-data/drafts/)、オーナー 2026-11-18）を、測量で埋める。ノード ID は `campus_n_001`〜`campus_n_013`（旧ラベル N01〜N13）、辺は `campus_e_001`〜`campus_e_014`。

### 5.1 ルートと基線

ルートを基線（`baselines`）に分ける。区切りはノードごと（ノードの間が直線のとき）。ウォーキングメジャーで進みながら、ノード・分岐・入口前・支距を下ろす点で累積距離を読む。

- **累積距離（`chainage_m`）は、その基線の起点（`from` のノード）からの距離で書く**。ツールはこの値を基線の起点からの距離としてそのまま使う。
- そのため、**ノードに着いて次の基線に移るたびに、ウォーキングメジャーを 0 に戻す**。戻し忘れたときは、表示の値から次の基線の起点（そのノード）での読みを引いた値を書き、メモに元の読みを残す。例: N01→N02 が 100.0 m で、0 に戻さずに N02→N06 を 40.0 m 進んだら、表示は 140.0 m、書くのは 40.0 m。
- ノードでの読み（前の基線の終わり）は、前の基線の行に「その基線の終点までの長さ」として残る。ノード自身は次の基線の累積距離 0.0 m の点になる。

| ルート | 経路（起点 → …。ノードごとに基線を切り替える） | 支距を測る棟 |
|---|---|---|
| ルート1（背骨） | `campus_n_001` 正門 → `campus_n_002` → `campus_n_006` → `campus_n_007` → `campus_n_008` → `campus_n_010` | `ctc2`（N06）・`ctc_main`（N07） |
| ルート2（南エリア） | `campus_n_010` → `campus_n_011` → `campus_n_012` → `campus_n_013` | `hgr_a`・`hgr_b`（N11）・`sab`（N13） |
| ルート3（東外周〜北） | `campus_n_010` → `campus_n_009` → `campus_n_004` → `campus_n_003` → `campus_n_002` | `amh`（N04、`dh` との隙間も） |
| ルート4（西側） | `campus_n_002` → `campus_n_005` → `campus_n_007`（通れるか確かめる） | `dvh`（N05） |

- ルート1 と ルート3 で `campus_n_002` → … → `campus_n_010` の輪ができる（§4.7）。測量設定の `loops` に書く。
- 各ノードには、国土地理院で確かめた古い棟の角からの距離を最低1本（結合）。

### 5.2 測量設定への書き方

- ノード・入口・折れ点を `points` に（`kind` は `node`・`entrance`・`bend`）。
- 基線を `baselines` に（`{ "id": "R1-01", "from": "campus_n_001", "to": "campus_n_002" }` など）。
- 辺を `edges` に（`{ "id": "campus_e_001", "points": ["campus_n_001", "campus_n_002"] }`。折れ点があれば間に入れる）。
- 輪を `loops` に（`{ "id": "loop-n02-n10", "points": ["campus_n_002", "campus_n_006", "campus_n_007", "campus_n_008", "campus_n_010", "campus_n_009", "campus_n_004", "campus_n_003"] }`）。

ツールは `--points-out` でノード・入口・折れ点の Point を、`--routes-out` で辺の LineString と `distance_m`（調整後の折れ線の長さ）を出す。下書き CSV の `distance_m` の埋め方は [`map-data/drafts/README.md`](../../map-data/drafts/README.md)。

## 6. 試行（本番の前に）

本番の日の前に、短い時間で次を試す。

1. **ウォーキングメジャーの校正**: 巻尺で 50 m を正確に測った直線の舗装面を、ウォーキングメジャーで**行きと帰りの両方**測る。表示 ÷ 50 m を `scale_factor` とし、測量設定の機材に書く（例: 行き 50.6・帰り 50.4 → 平均 50.5 → `scale_factor` 1.01）。行きと帰りの差が 0.5 m を超えたら、車輪の滑りを疑ってやり直す。
2. **1棟と1つの分岐を試す**: 基準点に近い新しい棟（`ctc2` など）を1棟と、ノードを1つ、本番と同じ方法（支距・3本目の距離・W×D・対角線）で測る。

## 8. 測った値から GeoJSON を作る

### 8.1 方法

[`tools/map-dataset/survey.mjs`](../../tools/map-dataset/survey.mjs)（実体は `src/survey/`、テストは `test/survey.test.mjs`）。新しいライブラリは入れていない（既存の `transform.mjs` の WGS 84 ↔ 局所ENU を使う）。

1. 基準点（国土地理院の座標）を、キャンパスの原点のまわりの**局所ENU**（メートル）に変える（E1-5 と同じ計算。原点は測量設定の `origin`、無ければ基準点の平均）。
2. 斜距離を水平距離に直し（§4.5）、機材の `scale_factor` で割って目盛りを直す（§6）。
3. 各点の初期値を決める。支距があれば基線から直接置く。距離だけなら2つの円の交点で、**交わる角が直角に近い組から順に**試し、3つ目の距離か方位で2候補のどちらかを決める。方位は初期値にだけ使い、計算の精度には入れない。
4. 距離・累積距離・支距の観測を、**重み付き最小二乗**（Gauss-Newton）でまとめて解く。基準点は固定。重みは機材ごとの `sigma_m + sigma_per_m × 長さ`。累積距離には、直角の誤差（`right_angle_sigma_deg`、既定 1°）× 支距 を足す。
5. 残差・各点の標準偏差・自由度・単位重みの標準偏差（σ0）・基準点の照合・輪の閉合差を出し、§4.8 の基準で「測り直し」を判定する。
6. 点を WGS 84 に戻し、**小数6桁**に丸める。建物は反時計回りの閉じた環の Polygon、経路は LineString。

### 8.2 使い方

```bash
npm run mapdata:survey -- \
  --project <測量設定.json> \
  --observations <野帳.csv> \
  --report <レポート.json> \
  --out <建物.geojson> \
  --points-out <点.geojson> \
  --routes-out <経路.geojson> \
  --provenance-out <出典の行.csv>
```

- 測量設定のひな形: [`map-data/survey/templates/survey-project.template.json`](../../map-data/survey/templates/survey-project.template.json)（`survey_version` 1.1.0）。

| 項目 | 内容 |
|---|---|
| `references` | 基準点（§3 で確かめた角の、国土地理院の緯度経度と `building_id`）。`source` に Apple・Google を書くと拒否する |
| `instruments` | 機材ごとの `sigma_m`・`sigma_per_m`（数で書く。文字列は拒否）と、校正の `scale_factor`（任意） |
| `right_angle_sigma_deg` | 支距の直角の誤差（プリズム 0.5、3-4-5 で 1） |
| `buildings` | 建物ごとの角の順 |
| `points` | 角以外の点（`aux` 仮の点・`node` ノード・`entrance` 入口・`bend` 折れ点） |
| `baselines` | 支距の基線（`from` が累積距離 0。基線ごとに 0 に戻す） |
| `check_points` | 調整に入れない照合点（§9） |
| `edges`・`loops` | 経路の辺（§5.2）・閉合を確かめる輪（§4.7） |

- 終了コード 0 = すべて許容値内、1 = 測り直しがある（GeoJSON は書き出さない。`--allow-remeasure` で下見・試行用に書き出せる）、2 = 入力の誤り。
- レポートには、建物ごとの角の位置・標準偏差・残差、点の一覧、基準点の照合、輪の閉合差、斜距離の換算、精度（§9）、測り直しの一覧が入る。

### 8.3 野帳の列

| 列 | 内容 |
|---|---|
| `record_id` | 記録番号（重複不可） |
| `obs_type` | 空欄か `distance`（距離）、または `chainage_offset`（支距） |
| `building_id` | 測っている建物（経路なら空欄） |
| `point_id` | 測った点（新しい棟の角 `<ID>-P*`、古い棟の角 `<ID>-G*`、ノード `campus_n_*`、入口 `<ID>_ent_*`、折れ点・仮の点など） |

| `distance_m` | 距離: 長さ [m]。斜距離なら `slope_deg` か `height_diff_m` も書く |
| `slope_deg`・`height_diff_m` | 斜距離のときの傾斜角 [度] か高低差 [m]（片方だけ） |

### 8.4 原本と対応設定へのつなぎ方

- 新しい棟: ツールが出す GeoJSON は、map-dataset の `geojson` 原本と同じ形（`properties.id` に建物 ID）で、出典（`geometry_source`・`survey_dates`・`reference_point_ids`・`relative_accuracy_m_1sigma`・`absolute_accuracy` など）を `properties` に持つ。`reference_point_ids` には、仮の点・ノード・ほかの建物の角を経由してたどれる基準点もすべて入る。
- 古い棟（照合で合ったもの）: `fgd-to-geojson` の `--assign <gml_id>=<建物 ID>` で、国土地理院の形をそのまま（頂点を動かさず）`properties.id` 付きで出す。

  ```bash
  npm run mapdata:fgd -- --input <…-BldA-…xml> --out gsi-buildings.geojson \
    --assign K17_5094015390_35=ar --assign K17_5094015390_66=aptr …
  ```

- map-dataset は配布の GeoJSON に出典の項目を持ち込まない（E1-4 の `building` は `feature_type`・`name`・`access_node_id` だけ）。出典は §10 の表に残す。
- 2つの GeoJSON をリポジトリの外の原本フォルダ（今の `確定版geojson/` と同じ場所）に置く。原本 `nexus_campus_canonical_20260724.geojson` は**変更しない**。
- [`campus-buildings.config.json`](../../tools/map-dataset/config/campus-buildings.config.json) に `geojson` の原本を2つ足し（例: `survey_buildings`・`gsi_buildings`）、14棟の `features` の `source` をそちらに切り替える。旧原本の14棟は `exclude`（理由コード例 `superseded_by_survey`）にする。名前は国土地理院のデータに無いので、`explicit` か登録簿で決める。これは測量が済んでからの別の PR で行う。
- 経路のノード・辺・入口（`--points-out`・`--routes-out`）は、#16・#39 で正規化ソースと対応設定に入れる。

## 9. 精度の書き方

精度は2つに分けて書く。

| 精度 | 意味 | 目標・値 | 確かめ方 |
|---|---|---|---|
| **相対精度** | 構内の点どうしの位置関係の確かさ | 1σ 0.4 m 以下（95% でおおむね 1 m） | 最小二乗の各点の標準偏差（ツールの `relative_accuracy_m_1sigma`） |
| **絶対精度** | 地球上の本当の位置との差 | 基準点の精度に従う（地図情報レベル2500、位置の標準偏差 1.75 m 以内とされる） | **調整に入れない照合点**を測ったときだけ確かめられる。それまでは「未確認」 |

- 照合点: 基盤地図情報には、キャンパスの近くに基準点（`GCP`・`SBAPt`）が無い（2026-11-18 確認）。構内か近くに、座標の分かっている**公共の基準点**（国土地理院の「基準点成果等閲覧サービス」で探す。三角点・公共基準点など）があれば、測量設定の `check_points` に座標を書き、その点を基準点・ノードから2本以上測る。ツールは照合点を固定せずに位置を求め、本当の座標との差を `accuracy.absolute_check` に出す。
- 照合点が無ければ、絶対精度は**未確認**と記録する（ツールの既定）。JGD2024 と WGS 84 の差（§2.1）も、このとき確かめられない。
- スマートフォンの GPS は照合点にならない（誤差が大きすぎる）。
