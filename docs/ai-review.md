# MR自動AIレビュー

`.gitlab-ci.yml` の `ai-review` ジョブは、Draftではない同一プロジェクトのMRパイプラインで実行されます。新しいコミットがpushされると、古いレビューをキャンセルし、最新コミットのレビューだけを残します。

## 実行制御

- ブランチパイプラインとMRパイプラインの重複を防止する。
- 外部Fork MRは実行しない。
- `.gitlab-ci.yml` または `tools/ai-review.mjs` を変更したMRでは実行しない。
- 全MRのレビューをグローバルな `resource_group` で1件ずつ直列化する。
- 新しいコミットで古いレビューをキャンセルする。
- 1回のレビューにつき、OpenAI呼び出しは最大1回、GitLabのコメントは1件の更新または作成にする。
- 差分は最大120,000文字・120ファイルまでとし、超過時はAPIを呼ばずに終了する。
- APIの429・一時的な5xxだけ最大2回再試行し、`Retry-After`を尊重する。
- 認証エラーやコメント投稿失敗を無限再試行しない。
- レビュージョブは `allow_failure: true` とし、レビューサービスの障害でマージをブロックしない。

## CI/CD変数

プロジェクトの Settings > CI/CD > Variables に次の変数を登録します。

| 変数 | 用途 | 設定 |
|---|---|---|
| `OPENAI_API_KEY` | OpenAI APIキー | Masked and hidden。YAMLには書かない |
| `OPENAI_MODEL` | 使用モデル | 例: `gpt-5-mini`。利用可能なモデル名を指定 |
| `GITLAB_REVIEW_TOKEN` | MRコメント投稿用のプロジェクトアクセストークン | 最小限のスコープで作成し、Masked and hidden |

トークンの値はチャットやコミットに貼り付けないでください。Fork MRを対象にする場合は、秘密情報をMRブランチへ渡さない別構成が必要です。

## コメントの扱い

MRごとに `<!-- nexus-ai-review -->` を含むコメントを1件だけ管理し、コミット更新時は同じコメントを更新します。承認、マージ、修正コミットの作成は行いません。
