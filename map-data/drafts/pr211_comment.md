## キャンパス地図データ作成・再計測方針の整理

Apple / Google の地図から座標・形状を抽出せず、「国土地理院（基盤地図情報・空中写真）＋ 現地実測（ウォーキングメジャー）＋ 自身の知識」のみで v1.0 の案内データを揃える方針・手順の整理です。

### 1. 基本方針（規約・技術制約との整合）
- **MapKit での 3D 表現**: SwiftUI の `MapPolygon` は 2D（平面）のみ対応で、独自データによる 3D 建物押し出しは標準 API では不可（`E3-1` / `E1-4` の 2D 契約とも整合）。背景を `.mapStyle(.standard(elevation: .realistic))` で 3D 表示しつつ、自前データは 2D ポリゴン・ピンとして重ねる。
- **MapKit からの座標抽出は行わない**: 基盤地図情報（古い7棟・道路縁）と現地実測から WGS 84 座標を算出し、Apple の地図との数 m のズレは表示上の工夫（非選択時は枠を出さない／選択時のみ枠表示など）で吸収する。
- **現在地とグラフの結合**: iPhone 単体 GPS 誤差（5〜19 m）を前提とし、`entrances.csv` の位置に基づく最寄り出発地サジェスト ＋ 手動選択 / QR 確定のハイブリッドで扱う。

### 2. 道路ネットワークの区画整理（13ノード・14区間）
`map-data/drafts/campus_nodes_draft.csv` および `campus_edges_draft.csv` として下書きを作成済み（`N01` 正門 〜 `N13` 技能審査棟）。
- 長さだけのパズルでは四角形ループの角度自由度が残るため、基盤地図情報（古い7棟・道路縁）を動かない台紙とし、分岐・入口前で累積距離を区切る。
- 途中に分岐がない曲がり角は無理に分割せず 1 エッジとし、線形状が必要な場合のみ折れ点から建物壁への距離を測る。

### 3. 建物形状・位置の計測ルール
- **形状**: 外周を 1 周せず「全体の縦 × 横」で測る（コの字型は `全体の幅 W・奥行 D − 凹み w・d・端からの距離 a` で計算し、辺の合計ズレを防ぐ）。壁から 2〜3 m 離れた舗装面を平行に歩く「平行オフセット法」を使用。
- **位置（支距法）**: 新しい 7 棟（`ctc2`, `ctc_main`, `hgr_a`, `hgr_b`, `sab`, `amh`, `dvh`）は、手前 2 つの角について「道路上の累積距離 (`s1`, `s2`)」と「道路からの垂直距離 (`d1`, `d2`)」をセットで測り、位置と傾きを確定させる。
- **入口未記録の 2 棟**: `ptb`・`aptr` が屋外直結入口を持たない（`mb` から屋内連絡）運用か現地で確認する。

### 4. 現地計測メモ（累積距離＋支距法テンプレート）
- ルート1（背骨）：`N01`（0.0m）→ `N02` → `N06`（`ctc2` 支距）→ `N07`（`ctc_main` 支距）→ `N08` → `N10`
- ルート2（南エリア）：`N10`（0.0m）→ `N11`（`hgr_a` / `hgr_b` 支距）→ `N12` → `N13`（`sab` 支距）
- ルート3（東外周〜北）：`N10`（0.0m）→ `N09` → `N04`（`amh` 支距・`dh` との隙間）→ `N03` → `N02`
- ルート4（西側）：`N02`（0.0m）→ `N05`（`dvh` 支距）→ `N07` 抜け道確認
